# Figma 반입 작업물

프로토타입의 모든 화면·상태를 Figma에 **편집 가능한 레이어**로 올려, 팀이 댓글로
UX를 같이 뜯어보기 위한 자료. 2026-09-14(월) 주간회의용.

여기 있는 것은 전부 **프로토타입에서 파생된 산출물**이라 프로토타입 옆에 둔다.
`daesingo-screens-sheet.html`은 `scripts/build-sheet.mjs`가 굽는 결과물이므로 손으로 고치지 않는다 —
고칠 것이 있으면 `src/`를 고치고 다시 굽는다.

## 왜 만들었나

멘토 리뷰(PR [#21](https://github.com/kakaotechcampus-4/ktc4-chonnam-2/pull/21))의 UX 지적 두 가지가 출발점이다.

> 여전히 유저가 신경쓸게 많습니다. (…) sd카드에서 영상 뽑고 넣은 다음 몇시쯤 ...한 상황이
> 있었어(초반 화면이죠?) 만 넣어준 다음에 자고 일어나면 알아서 신고가 되어 있으면 좋겠어요.
> 유저들은 생각보다 동선에 민감합니다. **단계 하나 추가될 때마다 사용자 수가 꽤 줄어들어요.**
> (…) 지금의 동선은 일단 변경 없이 구현하시고, **'간편신고'로 따로 기능을 만드시는게** 좋을 것 같습니다.

여기에 기술멘토링에서 나온 **"글자가 너무 많다"** 가 더해진다.

두 지적 모두 **실제 문구가 붙은 화면을 늘어놓고 봐야** 고칠 수 있다. 그래서 회색 상자
와이어프레임이 아니라 프로토타입 화면 그대로를 반입한다.

## 반입된 Figma 파일

<https://www.figma.com/design/pBpFyBB5nU5bBOePGRZmzh> — `daesingo` 팀, 2026-09-12 반입.

프레임 이름은 이 폴더의 문서와 같은 ID를 쓴다(`07-prepare-needs-review` 등). 각 프레임 밑은
`· 라벨` / `· 화면` / `· 질문` 세 블록이다.

파일에 얹은 주석 레이어 — **화면 자체가 아니므로 논의가 끝나면 지워도 된다**:

| 레이어 | 무엇 |
| --- | --- |
| `간편신고 검토 · 덮개` | 멘토안 검토용. A 레인 04~08을 덮는다 |
| `간편신고 검토 · 멘토가 남긴 화면` | 03·09 초록 테두리 |
| `간편신고 검토 · 질문` | 「이 다섯 화면을 없애면 무엇이 깨지는가?」 |
| `분기 · …` | 05→B, 07→C 화살표와 레인 설명 |

> 반입 시 **Pretendard가 Figma에 없어 Noto Sans KR로 대체**된다(CSS 폴백과 같은 순서).
> 자소 모양이 조금 다르므로 자간·줄바꿈을 Figma에서 최종 판단하지 않는다.

## Figma에 올리는 법

1. Figma에서 새 파일을 만들고 **html.to.design** 플러그인을 연다
2. **Import from HTML code** 탭을 고른다
3. `daesingo-screens-sheet.html`을 텍스트 편집기로 열어 **전체 복사 → 붙여넣기**
4. 반입 폭은 **1600px**로 둔다 — 시트가 1600px 뷰포트 기준으로 구워져 있다
5. 반입이 끝나면 레인 4개(A 메인 동선 / B 결과 분기 / C 번호판 변형 / D 값이 비었을 때)가
   그대로 들어온다. 각 화면 프레임에는 `data-artboard` 이름(`07-prepare-needs-review` 등)이 붙어 있다

> 폭이 1600px보다 좁게 반입되면 `global.css`의 미디어 쿼리가 2단 레이아웃을 1단으로 접는다.
> 그러면 실제 화면과 다른 그림이 Figma에 들어간다.

## 화면 19장 구성

| 레인 | 아트보드 |
| --- | --- |
| **A · 메인 동선** | 01 업로드(진행) · 02 업로드(완료) · 03 진술 · 04 이해 확인 · 05 찾는 중 · 06 후보 확인 · 07 번호판 확인 · 08 제출 전 검토 · 09 전달 |
| **B · 결과 분기** | 10 결과 없음 · 11 범위 확장 후 재검색 · 12 비슷하지만 다른 장면 · 13 중간에 멈춘 결과 · 14 검색 실패 · 15 실패 전까지 찾은 것 |
| **C · 번호판 변형** | 16 판독 불가 · 17 선명 · 18 확인 완료 |
| **D · 값이 비었을 때** | 19 발생시각 미상 |

각 화면 아래에 **회의에서 물을 것**(주황 테두리 블록)이 붙어 있다. Figma 댓글은 그 블록이나
화면 요소 어디에나 달면 된다.

## 다시 굽는 법

프로토타입을 고친 뒤 시트를 갱신하려면:

```bash
npm run build --workspace=daesingo-prototype
node apps/prototype/scripts/build-sheet.mjs
```

`아트보드 19장 · 고정 완료`가 찍히면 이 폴더의 HTML이 갱신된 것이다.
Chrome이 기본 경로에 없으면 `CHROME_PATH` 환경변수로 알려준다.

브라우저에서 직접 보려면 `npm run sheet` (창을 1400px 이상으로 최대화할 것).

## 시트가 어떻게 만들어지는가

- 화면 상태를 손으로 적지 않는다. `apps/prototype/src/sheet/artboards.ts`가 실제
  `machine.ts`의 `reduce()`에 액션을 흘려서 각 상태를 만든다 — 프로토타입이 바뀌면 시트도 따라 바뀐다
- 화면 자체 타이머(업로드 3초, 검색 진행)를 다 돌린 **뒤** DOM을 얼린다. 그래서 언제 구워도 같은 그림이 나온다
- 시트의 조작 UI(상단 바·안내문)는 구울 때 빠진다. Figma에는 화면과 질문 블록만 들어간다
- 프로토타입 본체(`App.tsx` 등)는 **건드리지 않았다.** 같은 화면 컴포넌트를 읽기만 한다
