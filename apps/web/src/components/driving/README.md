# 선택해서 여는 주행 화면

`FlowScreen`의 기존 미리보기 영역을 사용한다. `coarse_search`가 `RUNNING`이고 blocking notice가 없을 때, 미리보기 안 오른쪽 위에 `기다리는 동안 게임을 해보시겠어요? >`를 한 줄로 표시한다. 문구 전체를 누르면 게임을 열고, 돌아온 뒤에는 `주행 게임 >`로 줄인다. 새 분석에서는 다시 초대 문구를 표시한다. 원본 없음·디코딩 실패·4초 시간 초과에도 게임을 자동으로 열지 않는다. 사용자가 처음 선택할 때만 주행 엔진을 불러온다.

게임 안 왼쪽 위의 `<`는 커서·키보드 포커스에 `< 돌아가기`로 펼쳐진다. 터치에서는 문구를 항상 표시한다. 돌아가면 같은 썸네일을 보여주고 주행·렌더링을 멈춘다. 다시 선택하면 위치·기어·사용자가 선택한 일시정지 상태를 유지한다. 전체 화면에서 돌아가면 먼저 전체 화면을 종료한다.

- `DrivingPreview.tsx`: 지연 로딩, React 생명주기, 접근성·대체 안내. 분석 상태는 부모가 결정한다.
- `createDrivingScene.js`: 승인된 독립 주행 데모의 렌더링·조작·교통 시뮬레이션. typed boundary는 `.d.ts`에 둔다. 브라우저 안에서만 실행하며 API나 CaseView를 읽거나 변경하지 않는다.
- `rules.ts`: 차량·보행자가 함께 사용하는 신호 주기와 횡단 위치. 실제 도로의 신호 시간표가 아닌 시뮬레이션이다.
- `driving.css`: 기존 미리보기 안의 조작 배치와 선택적 브라우저 전체 화면. 바깥 페이지 레이아웃은 바꾸지 않는다.

장면 찾기 종료·중단·화면 이탈 시 애니메이션, 리스너, observer, WebGL 자원과 전체 화면을 해제한다. 탭 숨김·화면 밖에서는 렌더링을 멈추며, 동작 줄이기 설정에서는 정지 상태로 시작한다. 일시정지와 P/D는 주행 화면에만 영향을 준다. WebGL 초기화 실패·컨텍스트 유실에는 기존 미리보기 불가 안내를 표시한다.

## 확인 방법

루트에서 `npm run test:web`과 `npm run build --workspace=daesingo-web`을 실행한다. 썸네일 성공/실패/시간 초과, 지연 로딩 중 해제, StrictMode, 그래픽 실패, 차량·보행자 신호 충돌은 단위 테스트로 확인한다.

브라우저에서는 `npm run dev:web`의 `?api` 흐름으로 다음을 확인한다. 실제 분석 E2E에는 HTTP 서버와 분석 worker가 필요하다.

1. 재생 가능한 영상을 올려 장면 찾기 시작 → 기존 썸네일과 게임 진입 버튼 표시, 선택 전 주행 엔진 미요청.
2. 미리보기를 만들지 못하는 영상 또는 원본 없는 재접속 case → 미리보기 불가 안내와 게임 진입 버튼 표시. 선택하면 같은 영역에서 게임을 시작하고, 돌아갔다 다시 열어도 주행 위치 유지.
3. 핸들 화살표·P/D·일시정지 → 분석 command가 추가로 전송되지 않고 `/view` 조회 계속.
4. 크게 보기·축소, 장면 찾기 종료·분석 중단 → 전체 화면 종료와 canvas 제거.
5. 작은 화면, 동작 줄이기 설정, WebGL 불가 환경 → 잘리는 조작이나 분석 화면 오류 없음.
