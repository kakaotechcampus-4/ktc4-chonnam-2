# 분석을 기다리는 동안 하는 드라이브

기존 FlowScreen의 영상 미리보기에서 사용자가 선택했을 때만 게임을 연다. 분석이 진행 중이고 blocking notice가 없을 때의 진입 조건과 소프트웨어 WebGL 환경에서 진입을 숨기는 조건은 유지한다. 게임의 거리·레벨·동전·보호막은 브라우저 안의 놀이 상태이며 CaseView나 분석 command와 연결하지 않는다.

## 실행과 수명

- DrivingPreview.tsx가 돌아가기와 로딩·실패 안내를 담당한다.
- createDrivingScene.js는 같은 origin의 driving-game.html을 지연 로딩한다. iframe으로 게임의 폰트·뷰포트·키보드·터치 영역을 격리한다. Three.js는 게임 선택 전에는 요청하지 않는다.
- game/의 JS와 CSS가 게임 원본이다. Vite가 게임 HTML도 별도 진입점으로 빌드한다. 생성된 번들이나 로컬 파일 경로를 소스에 넣지 않는다.
- 돌아가기·화면 밖에서는 렌더링과 입력을 멈추고 상태를 유지한다. 포커스를 잃거나 탭을 숨기면 일시정지하며 계속하기로 재개한다.
- 게임의 전체 화면은 부모 media 영역에 적용하므로 돌아가기 버튼도 함께 보인다. 분석 완료·중단·화면 이탈 시 iframe, RAF, 입력 리스너, observer, 소리와 WebGL 자원을 정리하고 전체 화면을 종료한다. 마지막 신고의 게임 상태는 메모리에 보관해 같은 신고에서 후보를 다시 고른 뒤 게임을 열면 일시정지한 레벨·거리·동전·보호막부터 이어간다. 다른 신고의 게임을 열거나 페이지를 새로고침하면 새 게임이다.
- 그래픽 초기화 실패나 컨텍스트 유실은 게임의 실패 안내로 한정한다. 분석 진행은 그대로 이어진다.

## 게임 규칙

방향키 좌우 또는 드래그로 차선을 바꾸고, 위 방향키 또는 Space로 점프한다. 짧게 한 번은 짧은 점프, 빠르게 두 번은 높은 점프, 누르고 있기는 부스트이며 놓으면 내려온다. 긴 점프 중에는 한 번 회전한다. 모션 감소 설정에서는 회전을 생략한다.

HUD는 레벨 왼쪽·거리 오른쪽, 시속은 오른쪽 아래다. 점수와 별도 사용 횟수는 표시하지 않는다. 동전 10개당 보호막을 얻되 한 판에서 누적 3개까지만 얻고 사용하며 재충전되지 않는다. 게임 종료 후 레벨과 거리를 보여 준다. 레벨 1만 조작 안내를 표시하고 레벨 변경은 별도로 알린다.

17레벨부터 열린 차선이 달라지는 공사벽 3~5줄과 낮은/높은 차량을 섞는다. 벽 뒤 간격은 약 59m에서 25레벨 약 51m까지 좁아지고, 31레벨부터 약 45m로 유지한다. 원본은 game/course.mjs와 game/rules.mjs다.

## 검증

레포 루트에서 npm run test:web 및 npm run build --workspace=daesingo-web을 실행한다. 기존 썸네일/분석 흐름 회귀, StrictMode, 늦은 로딩, 복귀·해제·전체 화면, 화면 밖 중지, 그래픽 실패와 점프·동전·최종 난이도 테스트를 포함한다. 31레벨 테스트는 40개 코스를 45레벨까지 검사하며, 카메라가 벽을 지난 뒤 150ms 반응 지연을 둬도 보호막 없이 통과해야 한다.

실제 브라우저에서는 ?case=<id> 분석 화면에서 게임을 열어 조작 중 /view 폴링이 유지되고 새 command가 생기지 않는지, 결과가 도착하면 게임이 정리되는지 확인한다. 실제 분석 E2E에는 API 서버와 worker가 필요하다. 자동 입력 검사는 사람의 체감 난도를 대신하지 않는다.
