# product

제품의 **WHAT / WHY / 사용자 약속 / 검증할 제품 가설**을 관리한다.

## 이 폴더에 넣는 것

- 문제 정의와 타깃
- 제품 범위(Must / Won't)
- 핵심 사용자 흐름과 실패 UX
- 사용자 문제·행동 검증 근거
- 제품 전략과 장기적으로 남길 자산
- 사용자 검증 계획

## 이 폴더에 넣지 않는 것

- 모델·프롬프트·OCR·파일 처리 구현 상세 → `modules/`
- cross-module 소프트웨어 경계 → `architecture/`
- 평가 구현과 실험 결과 → `modules/eval/`
- 역할·일정·회의 결정 → `management/`

기술 구현이 바뀌었다는 이유만으로 `product-spec.md`를 수정하지 않는다. 사용자 약속, 지원 범위, 안전 경계, 제품 성공 정의가 바뀔 때만 수정한다.
