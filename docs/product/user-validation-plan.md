# 사용자 검증 계획 (User Validation Plan)

> Migration source: 서비스 기획안 1.3. 실제 사용자 검증 결과는 아직 기록되지 않은 상태로 옮겼다.

## 문서 목적

이 문서는 대신고가 해결하려는 문제가 **실제 사용자에게도 중요한 문제인지**, 그리고 대신고가 그 문제를 실제로 줄여주는지를 확인하기 위한 사용자 검증 계획을 정리한다.

기술 성능 자체를 평가하는 문서가 아니라, **사용자가 실제 신고 과정에서 어디에서 불편을 느끼고, 대신고를 사용했을 때 직접 작업시간·검토부담·신고 완료 행동이 어떻게 달라지는지**를 확인하는 데 목적이 있다.

## 1. 주요 사용자 모집 채널

**보배드림 교통사고/블랙박스 게시판**

필요한 사용자는 단순한 운전자가 아니라, **실제로 블랙박스 영상에서 사건 장면을 찾아 교통위반 신고를 준비해봤거나 준비 과정에서 신고를 포기해본 사람**이다.

## 2. 검증하고 싶은 것

- 사건 장면을 다시 찾는 과정이 **신고자료 준비(Evidence Preparation)에서 가장 큰 불편인지** 확인한다.
- 영상 탐색, 편집, 위치 확인, 신고내용 작성에 각각 실제로 얼마나 시간이 드는지 확인한다.
- 신고 준비 과정에서 사용자가 가장 번거롭게 느끼는 단계가 무엇인지 확인한다.
- 신고를 준비하다 중간에 포기한 경험이 있는지, 있다면 어떤 이유 때문인지 확인한다.
- 사건 장면과 신고자료가 자동으로 준비된 상태가 사용자의 직접 작업시간과 검토부담을 줄이는지 확인한다.
- 자동 준비된 결과가 **안전신문고 제출 단계로의 연결(handoff)**과 실제 신고 제출 행동에 영향을 주는지 확인한다.

## 3. 실제 행동 인터뷰 — 10명

미래에 사용할 의향보다 **지난 실제 신고 경험과 행동**을 중심으로 묻는다.

- 지난번 신고에서 사건 영상을 어떻게 다시 찾았는가?
- 영상 탐색, 편집, 위치 확인, 신고내용 작성에 각각 얼마나 시간이 걸렸는가?
- 가장 귀찮거나 번거로웠던 단계는 무엇이었는가?
- 신고를 준비하다 중간에 포기한 적이 있는가? 있다면 왜 포기했는가?
- 신고하게 된 이유는 위험 경험, 불공정하다는 느낌, 생활권 문제 개선, 처리 결과 확인 중 무엇과 가장 가까웠는가?
- `굳이 신고까지 해야 하나`, 직접적인 보상이 없음, 신고자에 대한 부정적 인식, 불수용·처리 지연 등 신고를 망설이게 한 요인이 있었는가?

## 4. 대신 처리해보는 검증(Concierge Test) — 10명

사용자의 과거 블랙박스 영상을 받아 팀이 직접 사건 장면을 찾고 신고자료 준비를 대신 수행해보면서, **자동화 기능을 완전히 구현하기 전에도 사용자가 이 결과에서 실제 가치를 느끼는지** 확인한다.

이번 문서에서는 구체적인 진행 방식이나 성공 기준을 새로 추가하지 않고, 기존 1.3에서 정한 범위만 유지한다.

## 5. 시제품 비교 테스트(Prototype Test) — 30명

기존 수동 신고 준비 방식과 대신고 시제품을 비교한다.

1.3에서 기록한 주요 관찰 항목은 다음과 같다.

- 사용자 직접 작업시간
- 사용자가 확인해야 한 사건 후보 수
- 사용자 수정 횟수
- 신고 준비 완료 여부
- 안전신문고 제출 단계까지 연결되었는지 여부(handoff)
- 실제 신고 제출 행동

## 6. 실행 상태와 결과의 기록 위치

**실행 상태와 검증 결과는 팀 Notion에서 관리하며, 이 문서에는 결과를 적지 않는다.** 인터뷰 응답과 관찰 기록은 개인정보를 포함할 수 있고 이 레포는 공개되므로, git에는 계획만 남긴다(`management/cross-cutting-decisions.md` C-1).

- 담당: 진행·분석 김준영(PM) / 측정·분석 김대원(`eval`) / UX 관찰 신유민(`web`) / 모집은 전원이 각자 지인에게 추천
- 집계 지표(작업시간 · 후보 수 · 수정 횟수 · handoff율)의 공개 여부는 결과가 나온 뒤 따로 판단한다.

실제 사용자에게서 얻은 학습 내용(user learning)은 프로젝트 운영 과정에서 주기적으로 확인하고 반영한다.
