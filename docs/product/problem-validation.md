# 문제 검증 (Problem Validation)

## 문서 목적

이 문서는 대신고가 **어떤 사용자 문제를 해결하려는지, 현재까지 무엇이 확인되었고 무엇이 아직 가설인지**를 정리한 문제 검증 문서다.

직접적인 구현 명세서나 AI 평가셋 설계 문서는 아니며, 다음과 같은 상황에서 참고한다.

- 제품 기능의 우선순위와 범위를 결정할 때
- 새로운 기능이 실제 사용자 문제와 연결되는지 확인할 때
- 사용자 테스트에서 무엇을 검증해야 하는지 정할 때
- AI·제품 평가 지표와 실험 방향을 설계할 때
- 기획 변경 시 기존 문제 정의와 근거를 다시 확인할 때

이 문서의 역할은 **“무엇을 구현할 것인가”보다 “왜 그것을 구현하는가”를 보존하는 것**이다. 실제 구현 방법은 Product Spec과 Architecture 문서에서, 구체적인 평가 데이터·지표·평가 절차는 Evaluation 관련 문서에서 관리한다.

## 1. 현재 사용자가 버티는 방식

### A. 완전 수동

```
교통위반 목격·신고 결심
→ 차량에서 SD카드 제거 / 앱에서 원본 확인
→ 노트북·리더기에 연결
→ 수분 단위 파일을 하나씩 열어 사건 순간 탐색
→ 필요한 구간 자르기
→ 130MB 등 첨부규격에 맞게 필요 시 압축
→ 영상 내 시각·차량번호 확인
→ 안전신문고에서 유형 선택
→ 위치 검색·지도 핀 세부조정
→ 날짜·시간·차량번호·신고내용 입력
→ 본인인증·인적사항
→ 제출
```

### B. 신고콕 같은 신고 보조도구

```
사용자가 위반 장면을 먼저 찾음
→ 영상 선택
→ metadata 촬영시각/위치 확인
→ 구간 자르기
→ 번호판 추출
→ 신고 4요건 확인
→ 신고문/법령 안내
→ 안전신문고 이동
→ 신고기록·기한·처리결과 관리
```

두 경로의 공통점은 **사용자가 먼저 어느 파일의 어느 순간이 신고할 사건인지 알아야 후반부 자동화를 시작할 수 있다는 점**이다.

신고콕은 대신고와 완전히 같은 제품이라기보다, **사건을 찾은 이후의 신고 준비 단계가 실제 서비스로 구현·운영될 수 있음을 보여주는 참고 사례이자 경쟁 서비스**로 본다.

## 2. 현재 드는 수고

- 여러 분할 파일·긴 타임라인에서 사건 순간을 다시 찾기
- 필요한 전후 구간 결정·자르기·재인코딩·첨부규격 맞추기
- 번호판이 선명한 순간 확인
- 실제 위반 시각 확인
- 운전 중 지나친 사건 장소를 안전신문고 지도에서 다시 특정
- 신고유형·요건·내용·본인인증 확인

### 20분 / 3분의 의미

- **박신고 20분:** 통계 평균이 아니라 `영상 찾기 10~15분 + 편집/용량 + 위치 재확인 + 정보입력`의 Proto-persona 시나리오.
- **3분:** total latency 보장이 아니라 **사용자의 직접 작업시간을 약 20분→3분으로 줄일 수 있는지 검증하는 목표값**.

## 3. 신고 동기와 저항

### 주요 동기 — 커뮤니티 관찰 기반

- 사고위험을 직접 경험했거나 위험행위를 목격함
- 얌체운전·규칙위반에 대한 불공정감
- 반복되는 생활권 문제를 개선하고 싶음
- 신고 수용·처리 결과에서 오는 완료감·성취감

### 주요 저항

- `굳이 신고까지 해야 하나?`
- 직접적 보상 없음
- 신고자에 대한 부정적 낙인 부담
- `나도 신고당할 수 있다`는 심리적 부담
- 불수용·처리지연 이후의 허탈감

UX는 `참교육·벌금·도파민`을 전면에 내세우지 않고 **안전·공정·신고 준비 완료·처리 결과** 중심으로 보상감을 설계한다.

## 4. 현재까지 확인된 것 / 아직 모르는 것

### 확인된 것으로 기록된 것

- 실제 신고 과정 캡처 자료(팀 아카이브의 `실제_신고_과정.pdf`, 레포 외부) 사례에서 SD카드 → 폴더 영상 탐색 → 편집 파일 첨부 → 위치 검색/핀 조정 → 신고내용·차량번호·날짜·시간 → 본인인증 workflow를 확인함.
- 커뮤니티 조사에서 블랙박스 영상 탐색·편집·용량 조정의 반복 불편이 관찰됨.
- 따라서 **긴 영상에서 사건 순간을 찾는 문제가 존재한다는 점은 정성적으로 확인된 상태**로 기록되어 있음.
- 후반부를 줄이는 신고콕 같은 실제 제품이 존재함.

### 아직 검증할 것

- 사건 재탐색이 신고 과정의 핵심/최우선 pain인가
- 실제 탐색/전체 준비에 얼마가 걸리는가
- 준비 과정 때문에 신고를 포기하는 비율은 어느 정도인가
- 자동 준비된 상태가 실제 신고 전환을 높이는가

사용자 조사에서는 미래 의향보다 **지난 실제 행동**을 묻는다.

> 지난번 실제 신고에서 영상을 어떻게 찾았고, 얼마나 걸렸으며, 어느 단계가 가장 귀찮았는가?

## 5. 시장/Impact 숫자의 사용 규율

1.3에 기록된 숫자는 다음처럼 사용한다.

### 사실/조사값으로 기록된 숫자

- 2023년 교통법규 위반 공익신고: 약 **366만 건**
- 전후 맥락·차량 움직임 확인이 중요한 대표 유형: 약 **203만 건**
- 안전신문고 동영상 한 파일 최대 **130MB**
- 교통법규 위반 공익신고의 **2일 이내 신고 urgency**

### 가설/시나리오

- `박신고 20분`은 평균이 아니다.
- `20분 → 3분`은 사용자 직접 작업시간 목표다.
- `약 57만 시간 절감`은 대표유형 약 200만 건 전체에 17분 절감이 적용된다는 potential impact estimation이다.

### 실측 전 하지 않는 주장

- ❌ 평균 20분이 든다.
- ❌ 정확도 90%다.
- ❌ 무조건 3분이면 끝난다.

대신 다음처럼 표현한다.

- ✅ 실제 신고 과정에서 해당 단계들이 존재함을 확인했다.
- ✅ `20분 → 3분`은 사용자 테스트를 통해 검증할 제품 목표다.
- ✅ 최종 AI 성능은 **사전에 고정한 실제 장시간 블랙박스 영상 데이터**를 기준으로 평가한다.

## 6. 실제 구현 사례

- **신고콕** — 사건을 찾은 이후의 촬영정보 확인, 영상 구간 자르기, 번호판 확인, 신고요건 점검, 신고문 작성 지원, 신고기한·기록 관리 기능을 실제 서비스로 구현한 사례
- **안전신문고** — 위치 검색·지도 핀 조정, 본인인증, 실제 신고 제출 과정이 어떻게 구성되는지 확인할 수 있는 공식 서비스
- **AI-Hub 경찰청 데이터** — 지원하려는 교통위반 유형과 관련된 주석 정보를 평가, 참고 자료, 향후 모델 학습에 활용할 수 있는 데이터 후보

## 7. 현재 문제 가설

> 교통위반 신고의 문제는 단순히 사람들이 신고할 의향이 없는 데만 있는 것이 아니다. **이미 신고하려고 마음먹은 사람도 영상 탐색·편집·시간·위치·차량번호 확인 등 신고자료 준비 과정이 번거로워 실제 제출 전에 포기할 수 있다.**

긴 영상에서 사건 장면을 다시 찾고 편집하는 등의 불편은 정성적으로 확인됐다. 다만 **이 과정이 실제 신고 준비에서 가장 큰 불편인지, 그리고 신고자료를 자동으로 준비해주는 것이 실제 신고 완료율을 의미 있게 높이는지는 아직 사용자 검증이 필요하다.**
