# RT-03(b) 구현 계획

> 승인된 `feature/runtime-job-claim-finish` branch에서 현재 세션으로 실행한다. 사용자는 NOW(6)/UTC session 및 STALE finish 없음 조건으로 설계와 실행을 승인했다. commit, push, PR 생성은 없다.

**목표:** Issue #290에 대한 짧은 영속 claim과 호출자 소유 terminal finish.
**아키텍처:** covering ID SELECT SKIP LOCKED, 조건부 UPDATE, PK 스냅샷, ACK를 받은 커밋. nullable 비공개 claim_token과 고정 execution ID로 RT-02 재시도 전반에 걸쳐 하나의 공개 호출을 식별한다. Finish는 호출자 트랜잭션에 참여한다.
**기술 스택:** SQLAlchemy Core, PyMySQL, Alembic, 실제 MySQL 8.4.
**명세:** 사용자가 승인한 대화 설계와 수정 사항; Runtime Plan §6 RT-03 및 §12, Tech Spec §4.2/4.3/4.5/6.3/12.1/12.4, JobExecution Contract §4–6/9, B-W3/B-L2/B-L6, S1/S2.

<a id="global-constraints"></a>

## 전역 제약

- claim 자격과 lease에 DB NOW(6)를 사용하고 애플리케이션/worker session은 UTC로 둔다. Baseline 변경은 없다.
- Finish 대상은 SUCCEEDED/FAILED/CANCELLED뿐이며 CANCELLED produced는 비어 있어야 한다.
- runtime_0001, Case 소유 파일, 보호 JSON, 기존 pytest scratch 폴더는 절대 수정하지 않는다.
- Claim callback에는 INSERT/handler/외부 I/O가 없다. ACK를 받은 커밋 뒤에만 반환한다.
- 불명확한 커밋 복구는 동일 execution ID/token을 읽는다. 불일치/분실/terminal은 오류이며 빈 queue가 아니다.
- worker loop/heartbeat/cancel 요청/STALE sweep/새 시도/usage/HTTP는 없다.
- 독립 재검토까지 RT-03를 IN_PROGRESS로 유지한다. 증거는 기존 scratch 폴더 밖에 보존한다.

<a id="review-focus"></a>

## 검토 초점

- 독립 호출의 같은 worker ID: receipt token을 구분한다.
- 재활용/재사용 session: 연결 교체와 timezone 오염 뒤에도 UTC를 유지해야 한다.
- ACK를 받은 커밋과 관측성 실패: 어느 쪽도 중복 재시도를 유발하면 안 된다.
- finish의 오래된 스냅샷: 경쟁은 이전 읽기가 아니라 조건부 UPDATE가 결정해야 한다.
- 불명확한 커밋 이후 만료 또는 terminal receipt: dispatch하거나 다른 행을 claim하지 않는다.

### 작업 1: Session과 전진 마이그레이션

- [x] UTC 초기화/checkout/교체, nullable token, 기존 행을 보존하는 runtime_0001 upgrade에 대한 실제 MySQL 테스트를 작성하고 RED를 실행한다.
- [x] 인덱스 없는 runtime_0002 nullable claim_token을 추가하고 live 메타데이터와 마이그레이션 기대값을 갱신한다.
- [x] UTC 애플리케이션/worker session 정책을 수정하고 대상 GREEN을 실행한다.

<a id="task-2-claim-and-finish"></a>

### 작업 2: Claim과 finish

- [x] 구현 전에 실제 MySQL claim/finish 테스트를 작성하고 lifecycle 함수 누락으로 실패함을 확인한다.
- [x] 전이 테이블을 바꾸지 않고 validate_transition(current, target)을 공개하며 memory store와 SQL 저장소에서 사용한다.
- [x] claim_one(engine, worker_id, *, lease_duration_sec=WorkerSettings default, logger=None)을 구현한다. 동결 DTO, 고정 ID/token, locking read를 통한 동일 행 복구, DB NOW(6), retry helper를 사용한다.
- [x] finish(conn, execution_id, owner, *, status, produced=(), failure_kind=None) -> int를 구현한다. 유효한 호출자 트랜잭션, 모델/ref 검증, DB ended_at, 조건부 UPDATE를 사용하며 트랜잭션을 소유하지 않는다.
- [x] 자격, 비어 있거나 잠긴 queue, INSERT 없음, 커밋/lock 경계, owner/status guard, 롤백, projection, EXPLAIN에 대한 대상 GREEN을 실행한다.

<a id="task-3-faults-and-deterministic-concurrency"></a>

### 작업 3: 결함과 결정적 동시성

- [x] 결과 분류 후 선택적 transaction-attempt 관측과 monotonic begin-to-commit 측정을 추가한다. sink 오류는 결과를 바꿀 수 없다.
- [x] 실제 1205/1213/disconnect 전체 재실행, 동시 claim, first-commit-wins, RC의 무관 행 finish를 Events/Barriers로 검증한다. sleep으로 성공시키지 않는다.
