## 개요

데모 영상은 두 편이다. 같은 블랙박스 폴더와 같은 사건을 쓰지만 목적이 다르다.

- **100초 발표용(발표자료에 넣는 영상):** 앞부분은 직접 신고, 뒷부분은 대신고로 같은 사건을 신고한다. 끝에 걸린 시간을 비교한다.
- **5분 이내 제출용:** 직접 신고는 넣지 않는다. 대신고가 단계마다 무엇을 하는지, 값이 확실하지 않거나 장면을 찾지 못하는 상황까지 차근차근 설명한다. 5분을 다 채우지 않아도 된다(현재 약 4분 30초).
- **샘플 영상:** `블랙박스_데모` 폴더(1분 파일 8개, 약 15분). 사건은 `20261026_161705_F.mp4`의 30–36초에 있다. 앞에 가던 은색 SUV가 노란 중앙선을 넘어 왼쪽 골목으로 들어간다.
- **두 번째 후보 — YouTube 합성 데이터:** 11/2 회의에서 나온 안대로, YouTube 긴 영상을 1분 단위로 나누고 타임스탬프 · 메타데이터 · 파일명을 블랙박스처럼 꾸민 데이터를 만들어 두었다. 지금 `블랙박스_데모` 8개 전체가 배포본에서 끝까지 분석되지 않아서, **두 데이터로 모두 돌려 보고 더 잘 나오는 쪽으로 찍는다.** 어느 쪽이든 두 편 모두 같은 폴더를 쓰고, 고른 결과는 이 문서의 사용 영상 목록에 적는다.
- **번호판:** 사건 차량에는 합성한 가짜 번호판 `157가 2846`을 넣었다. 주변 차량 번호판은 실제 번호판이다.
- **로컬 확인 결과(11/3):** 사건 파일 1개를 올리면 1순위 후보가 사건 장면(32.5초)이다. 위반 유형은 중앙선 침범, 번호판은 `157가2846`으로 읽혔다. 분석은 약 4분 걸렸다.
- **나레이션과 자막:** 장면마다 적은 나레이션 문장을 그대로 녹음하고, 같은 문장을 화면 아래 자막으로 띄운다. 「화면 문구」는 자막과 별도로 화면 위에 강조해 띄우는 짧은 글(값 이름, 시간, 고지 등)이다.

## 100초 발표용 시나리오

**같은 사건을 먼저 직접 신고하고, 이어서 대신고로 신고한다.** 서비스 설명은 발표자가 말로 하므로 영상은 차이만 보여 준다. 화면 오른쪽 위에 타이머를 띄운다. 타이머는 실측값이고, 줄인 구간에는 「배속」 또는 「대기 구간 단축」을 표시한다. ○는 촬영 후 실측값으로 채운다.

**사용 영상:** 두 쪽 모두 `블랙박스_데모` 폴더 8개 전체(A8)를 쓴다. 직접 신고 쪽은 이 8개를 하나씩 열어 장면을 찾고, 대신고 쪽은 8개를 한꺼번에 올린다. 사건 파일만 골라 올리면 「어느 파일인지 아는 사람」이 되어 비교가 성립하지 않는다. 영상 이름은 아래 「사용 영상 목록」과 같다.

### #1 0–5초 같은 사건

- **화면:** 사건 장면(`161705` 30–36초)을 전체 화면으로 보여 준다. 이어서 파일 8개가 든 블랙박스 폴더로 넘어간다.
- **나레이션 · 자막:** "같은 사건을 두 번 신고해 봤습니다. 먼저 직접 해 보겠습니다."
- **화면 문구:** 「블랙박스 영상 8개 · 약 15분」

### #2 5–40초 직접 신고

- **화면:** 직접 신고 녹화를 배속으로 이어 붙인다. 타이머가 계속 올라간다.
    1. 파일을 하나씩 열어 빨리감기로 장면 찾기
    2. 안전신문고에 첨부했다가 130MB 초과 오류
    3. 편집기로 사건 구간 자르기
    4. 영상을 멈추고 번호판 확대해 읽기
    5. 주소·제목·내용·일시를 손으로 입력하고 「신청」 직전에서 멈춤
- **나레이션 · 자막:** "파일을 하나씩 열어 장면을 찾고, 용량에 맞게 자르고, 번호판을 읽고, 신고서를 손으로 씁니다."
- **화면 문구:** 단계 이름 ①–⑤, 「배속」, 마지막에 「직접 신고 ○○분」을 크게 멈춰 둔다.

## 5분 이내 제출용 시나리오

**대신고 서비스만 보여 준다.** 직접 신고 장면은 넣지 않는다. 세 부분으로 나눠 차근차근 설명한다.

1. **기본 흐름(#1–#8):** 영상 올리기부터 안전신문고까지, 단계마다 「대신고가 하는 일 / 사용자가 하는 일」.
2. **값이 확실하지 않을 때(#2·#4·#5·#6 안의 「다른 상황」):** 단서·번호판·시각·위치가 불확실할 때 화면이 어떻게 달라지는지.
3. **찾지 못하거나 실패했을 때(#9–#10):** 원하는 장면이 아닐 때, 장면이 없을 때, 시스템 문제가 생겼을 때의 출구.

화면 문구는 현재 웹 앱 문구를 그대로 적었다. 장면마다 **사용 영상**에 아래 표의 영상 이름을 적었다. 「다른 상황」은 기본 촬영본으로는 나오지 않으므로 표의 영상으로 따로 찍는다. ○는 촬영 후 실측값으로 채운다. 모든 상황이 이 영상에 들어가지는 않는다. 넣은 것과 뺀 것은 아래 「상황별 포함 여부」에 정리했다.

## 주의사항과 금요일에 정할 것

촬영 전에 배포본에서 확인해야 할 문제가 두 가지 있다. 두 편 모두 결과 화면 장면이 여기에 달려 있다.

- **발생시각 12시간 오류는 고쳐졌다.** 영상 화면의 `04:17:34PM`을 04:17로 읽던 문제(#575)는 #578로 머지됐다(11/5). 촬영 전에 배포본에서 16:17:34로 나오는지만 확인한다.
- **100초 편은 폴더 전체를 올린다(`블랙박스_데모`면 8개, 약 15분).** 그런데 11/3 로컬에서는 파일 3개(약 3.9분)를 함께 올린 것도 후보 찾기 단계에서 멈췄고, 긴 입력은 #452로 고치는 중이다(11/5 Coarse 270p 변경 #572, 26분 E2E 준비 #582 머지, 이슈는 열려 있음). 촬영 전에 RC 배포본에서 8개 전체가 끝까지 분석되는지, 1순위가 사건 장면인지, 몇 분 걸리는지 확인한다. 안 되면 파일 수를 줄이는 대신 #452 담당(철원)과 일정을 다시 맞춘다.
- **번호판 고지.** 사건 차량 번호판 `157가 2846`은 합성이다. 두 편 모두 화면 문구로 밝힌다. 주변 차량의 실제 번호판은 편집할 때 흐림 처리한다.

금요일에 정할 것:

- [ ] 촬영일과 담당(직접 신고 녹화, 대신고 녹화, 다른 상황 추가 촬영, 편집)
- [ ] 나레이션 녹음 방식: 사람 목소리인가, 자막만 쓸 것인가

- [ ] 촬영 데이터: `블랙박스_데모` 8개인가, YouTube 합성 데이터인가(둘 다 배포본에서 돌려 보고 결과로 정함)
