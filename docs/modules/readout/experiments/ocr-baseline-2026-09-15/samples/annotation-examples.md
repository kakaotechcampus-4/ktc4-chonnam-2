# 어노테이션 형식 예시

검출 실험 정답지 후보들의 라벨이 실제로 어떻게 생겼는지 한 건씩 옮긴 것이다.
판정 근거는 `../../datasets-inventory-2026-09-18.md`에 있다.

## AI Hub 172 번호판OCR — bbox 없음

`Validation/[라벨]자동차번호판OCR_valid/01가3733.json` 전문:

```json
{"id":"b438c696-db6f-4a19-a1fc-7c7f39133694","imagePath":"01가3733.jpg","value":"01가3733"}
```

3필드가 전부다. 좌표·영역 정보가 없으므로 검출 정답지로 쓸 수 없고, recognition
정답지로만 쓸 수 있다. Validation 라벨 500개를 스캔해 `bbox`·`box`·`polygon`·
`points`·`coord`·`region` 계열을 찾았고 0건이다.

## Roboflow `Korean_license_plate` v2 — bbox 있음

`valid/labels/-30-2736_jpg.rf.3170b704b7297ebcf263a57e45c225d5.txt` 전문:

```
0 0.50078125 0.53125 0.7625 0.51484375
```

YOLO 형식 `class cx cy w h`(정규화)다. 클래스는 `0 = license_plate` 하나뿐이다.

이 한 건을 640x640에 환산하면 중심 (320, 340) · 폭 488px · 높이 330px다.
**이미지 높이의 51%를 번호판이 차지한다.** 블랙박스 실측 32~44px과 비교되는 지점이고,
이 데이터셋을 검출 정답지에서 제외한 이유다.

## 블랙박스 AVI — 라벨이 없다

`plate-crops-video-pilot.jpg`가 현재 가진 전부다. 번호판 영역을 사람이 잘라낸 것이
아니라 PaddleOCR detection이 찾은 박스를 crop한 것이므로 **정답지가 아니다.**
육안 대조로 확정된 값은 백색 1줄 `23두4874` 1건뿐이다.

## `plate-crops-video-pilot.jpg`

video pilot에서 검출된 번호판 후보를 시각화한 것이다. 원본 프레임이 아니라
**번호판 영역만 잘라낸 crop**이고, 주변 차량·보행자·촬영 위치는 포함되지 않는다.

| 타일 | 내용 |
| --- | --- |
| 위 5장 | `20260806_192353_EVT_1` 백색 1줄 · 1.74s / 6.08s / 10.42s / 14.76s / 19.11s |
| 아래 5장 | `20260810_175721_EVT_1` 황색 2줄 · 같은 시점 |

아래 5장에서 **윗줄(`전남 82`)이 육안으로도 뭉개져 있고 아랫줄 `바5215`만 선명하다.**
recognition이 아랫줄만 confidence 0.9979~0.9994로 5/5 만장일치 확정한 것이
모델의 변덕이 아니라 입력 자체의 성질임을 보여준다. README ①의 「구현이 막지 못하는
사례」가 이 이미지다.
