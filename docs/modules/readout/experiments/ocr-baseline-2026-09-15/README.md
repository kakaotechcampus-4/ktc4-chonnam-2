# 실제 OCR 실행 결과 + 실패 분류 태깅 (2026-09-15 실행)

readout이 **실제 영상과 실제 번호판 이미지에 OCR을 돌린 첫 실행**이고, 그 출력에
`decisions/failure-taxonomy.md`의 등재값을 붙인 것이다. 이 폴더가 P1 게이트(9/16~9/20)의
「실제 실행 결과 1개」에 대응한다.

`merge-evidence-2026-09-14/`와 다른 점 — 그쪽은 **구현이 fixture를 받아 만든 출력**이고,
여기는 **모델이 실제 픽셀을 보고 만든 출력**이다. 계약 준수 증빙이 아니라 측정이다.

재생성 — 태깅만:

```
python scripts/tag_ocr_failures.py
```

OCR 실행 자체를 다시 돌리는 것은 별개다. **이 실행은 레포 코드로 한 것이 아니고**
(`src/daesingo/readout`에는 OCR 실행 경로가 없다) 그때 따로 짠 스크립트로 했다.
그 스크립트는 `scripts/`에, 환경은 `ENVIRONMENT.md`에 있다. 환경이 이미 그대로는
재현되지 않는다는 점도 거기 적었다.

## 태깅에서 지킨 것

- **등재값만 쓴다.** taxonomy에 없는 상황은 값을 지어내지 않고 `null` + `open_question`으로
  남겼다(아래 「미결」). CLAUDE.md 4.
- **층위를 섞지 않는다.** 두 실행 모두 readout 공개 함수를 통과하지 않은 provider 단독
  측정이다. 따라서 여기 붙은 kind는 실제 기록된 `ReadoutRun.failure.kind`가 아니라 「같은
  상황이 readout을 통과했다면 붙었을 분류」이고, JSON 필드 이름도 `would_be_*`다.
  `OVERCONFIDENT`는 런타임 kind가 아니라 정답지 대조로 `eval`이 붙이는 사후 분류다.
- **정답을 지어내지 않는다.** 육안 대조값이 확정된 영상은 1개뿐이라 나머지 둘의 `visual_truth`는
  `null`이다.

## ① 블랙박스 AVI 3개 — 대표 5프레임씩

| 영상 | 조건 | 검출 | Exact | 분류 |
| --- | --- | ---: | ---: | --- |
| `20260806_061434_EVT_1` | 주행 · 원거리 · 횡방향 | 0/5 | — | `PLATE_DETECTION` |
| `20260806_192353_EVT_1` | 정지 · 정면 · 백색 1줄 | 5/5 | 3/5 | `PLATE_RECOGNITION` (프레임 2장) · run은 `FRAME_DISAGREEMENT`로 보류 |

### 구현이 옳게 막아낸 사례 — 백색 1줄

5프레임이 `23두4874` 3장, `2354874`(한글 누락, conf 0.907), `23투4874`(오인식, conf 0.944)로
갈렸다. **틀린 두 프레임의 confidence가 0.9를 넘는다** — confidence 단독으로는 거를 수 없다.
현재 `api.py`의 만장일치 consensus가 불일치를 잡아 `abstained=true` ·
`abstain_reason=FRAME_DISAGREEMENT`로 보류한다. 등재된 사유 하나로 정확히 떨어진다.

`_best_index()`가 고르는 대표 프레임은 conf 0.9800인 14.76s 프레임이고 그 값은 정답이다.
이 표본에서는 대표 프레임 선택이 우연히 옳았다 — 5프레임 1건으로 검증된 것은 아니다.

### 구현이 막지 못하는 사례 — 황색 2줄

아랫줄 `바5215`를 5/5 만장일치, confidence 0.9979~0.9994로 읽었다. 윗줄은
`4532` · `L532` · `전532` · `8732`로 흔들리거나(conf 0.375~0.621) 아예 검출되지 않았다.

**현재 구현이라면 그대로 확정된다** — 만장일치이므로 `abstained=false`, `status=OK`.
`api.py`는 문자열 일치·confidence·프레임 합의는 보지만 **번호판 완전성(1줄/2줄, 지역·분류줄)을
보지 않는다.** 이 값이 그대로 신고서에 올라가는 경로다.

> `bbox`도 여기서 갈린다. 검출 박스는 **텍스트 줄** 단위다 — 2줄 번호판에서는 아랫줄만
> 감싼다(높이 32~35px). 백색 1줄 영상의 39~44px와 같은 축으로 비교할 수 없고,
> `best_frame.quality.plate_px_height`와 계약 §4에 신설 예정인 `plate_bbox_xywh`가
> 「번호판 영역」을 뜻한다면 2줄에서는 그 전제가 깨진다. 계약 쪽 후속 항목이다.

## ② AI Hub Validation 500장 — recognition 단독

Exact 28/500(5.6%) · CER 55.3% · 빈 출력 94장. 이 표본에는 detection 단계가 없어
`PLATE_DETECTION`은 측정되지 않는다.

**빈 출력 94장은 confidence가 전부 정확히 `0.0`이다.** 고신뢰로 위장하지 않으므로
`status=UNKNOWN` · `value=null` 갈래로 안전하게 분리된다.

### 지역명(2줄 계열) 152장 — Exact 0장

정답에 지역명이 붙은 152장에서 **정확히 맞힌 것이 하나도 없다.** 나머지 348장의 Exact는
28장(8.0%)이다. 영상 pilot의 `바5215`와 같은 실패가 데이터셋에서 30%의 표본에 걸쳐 재현된다.
두 실행이 독립적으로 같은 결론을 가리킨다.

### 형식 gate를 통과한 오답 16건

형식 검사(자릿수·배치)를 통과하고도 틀린 것이 16건이고 confidence는 0.744~0.892다.
**이 16건은 confidence 0.90 gate 아래에 전부 깔려 있다** — 그래서 기준선 보고서의
「형식 + 0.90 → Wrong Accept 0」이 나왔다. 0.80으로 내리면 11건이 새고, 내역은 이렇다.

| conf | 통과 오답 | 용도문자 집합 위반 | 지역명 누락 | 설명 안 되는 것 |
| ---: | ---: | ---: | ---: | ---: |
| 0.80 | 11 | 8 | 3 | 0 |
| 0.90 | 0 | 0 | 0 | 0 |
| 0.95 | 0 | 0 | 0 | 0 |

- **용도문자 집합 위반 8건**은 `17더5966 → 17년5966`, `85서5618 → 85시5618`처럼 번호판에
  쓰이지 않는 글자(`년` `시` `는` `리` `매`)로 바뀐 것이다. 현재 형식 검사는 배치만 보고
  이것들을 통과시킨다. **용도문자 40자 집합을 닫는 검사만 추가하면 8건이 전부 걸린다.**
- **남는 3건은 전부 지역명 누락**(`경기37바5709 → 37바5709`)이다. 부분 판독 결과 자체가
  적법한 번호판 문자열이라 문자 집합으로도 형식으로도 걸리지 않는다. 위 ①의 2줄 문제와
  같은 뿌리이고, **완전성 검사 없이는 막을 수단이 없다.**

## 미결 — 이 실행으로 드러난 taxonomy 공백 2건

값을 여기서 만들지 않는다. taxonomy는 Owner(신유민) 소유 문서이므로 등재 여부를 따로 결정한다.

1. **`PLATE_DETECTION`의 `failure.code`가 등재돼 있지 않다.** taxonomy 「code」 표의 등재값은
   INFRA 3종뿐인데, `contract-readout-run.md` §4 예시 JSON은
   `{"kind":"PLATE_DETECTION","code":"NO_PLATE_REGION_FOUND"}`를 쓴다. 같은 계약의 규칙 4가
   「이 계약이 값을 추가하지 않는다」이므로 예시가 규칙을 어기고 있다. 영상 ①이 실제로 이
   경우다(검출 0/5). `OVERLAY_DETECTION`·`NO_OVERLAY_PRESENT`를 폐기한 것과 같은 성격의 건이다.
2. **「번호판 영역을 부분만 검출」에 해당하는 분류가 없다.** 영상 ③이 그 경우다. 영역을 못 찾은
   것(`PLATE_DETECTION`)도, 영역은 맞는데 문자를 잘못 읽은 것(`PLATE_RECOGNITION`)도 아니다.
   결과만 보면 사후 분류 `OVERCONFIDENT`가 맞지만, 그것은 `eval`이 정답지로 붙이는 값이라
   readout이 런타임에 쓸 수 있는 값이 아니다.
