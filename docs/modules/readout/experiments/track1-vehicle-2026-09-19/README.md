## 4. 설계에 돌려주는 것

| 발견 | readout 설계에 뭐라고 말하나 |
| --- | --- |
| hint 없는 association 최고 57.7% | `target_hint`는 계약상 optional이나(§696) **없을 때 그냥 진행하면 안 된다** |
| 틀릴 때 26~33%가 정상 차량 | 실패가 abstain이 아니라 **조용한 오답**으로 나온다 |
| 후보 2개 이상 84.6% | 「후보가 하나뿐」이라는 쉬운 경우는 드물다 |
| 위반 GT 2개 이상 7.4% (클립 12.4%) | 단일 대상 전제가 깨지는 경우가 있다. 계약이 이걸 표현할 수 있나 |
| **gaps = 0이 80.9%** | **tracker 도입 근거가 약하다.** 위치 근접 기반 묶기로 시작한다 |
| **2프레임 이상 검출 92.1%** | **`MULTI_FRAME` 합의 전제가 성립한다.** abstain 설계를 유지할 수 있다 |
| **크기 기준 Best Frame 25.8% < 프레임 단위 35.1%** | **「가장 큰 박스」로 대표 프레임을 고르면 안 된다** |
| oracle 71.9% · 같은 span에서 65.2%가 흔들림 | **한 장 고르기보다 여러 프레임 합의 쪽이 유리하다** |

**제안(결정 아님):** hint 없이 자체 association한 결과에는 낮은 신뢰도를 붙이거나
abstain하는 쪽으로 기울어 보이고, 대표 프레임 1장 전략보다 **multi-frame 합의**가
근거가 낫다. 다만 association 수치는 검출 박스만 쓴 바닥값이고 Best Frame은 정의를
하나만 시험했으므로, **결정은 span·사용자 단서를 쓰는 association과 다른 Best Frame
정의를 한 번 재 본 뒤로 미룬다.**

## 5. 검출기 선택 — 왜 COCO `yolo11n`인가

association의 **상한**을 만드는 부분이라 기록해 둔다.

| 후보 | 판정 | 이유 |
| --- | --- | --- |
| `EasyKoreanLpDetector` (`lp_det.pt`) | ❌ | **번호판** 검출기다. 대상 차량을 못 찾는다 |
| `sauce_onnx` `plate_detect_v1` | ❌ | 같은 이유 |
| `yolov5` (레포만 있음) | ❌ | 가중치가 없다 |
| **Ultralytics `yolo11n` (COCO)** | ✅ | 이미 깔린 `ultralytics==8.4.133`로 바로 돈다 |

**파인튜닝 0.** 기준선의 정의가 「손대지 않은 상태」이고, 지금 학습을 시작하면 그건
Challenger다 — 로드맵이 P4 Go/No-Go까지 막아 둔 일이다.
