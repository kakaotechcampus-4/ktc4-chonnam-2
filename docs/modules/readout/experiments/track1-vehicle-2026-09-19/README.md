## 1. 이 실험이 재는 것과 재지 않는 것

readout 책임은 `module-architecture.md` 모듈 3 ②에 8개가 있다. 이 실험은 그중

| | 재나? | 근거 |
| --- | --- | --- |

## 3. 설계에 돌려주는 것

| 발견 | readout 설계에 뭐라고 말하나 |
| --- | --- |
| hint 없는 association 최고 57.7% | `target_hint`는 계약상 optional이나(§696) **없을 때 그냥 진행하면 안 된다** |
| 틀릴 때 26~33%가 정상 차량 | 실패가 abstain이 아니라 **조용한 오답**으로 나온다 |
| 후보 2개 이상 84.6% | 「후보가 하나뿐」이라는 쉬운 경우는 드물다 |
| 위반 GT 2개 이상 7.4% | 단일 대상 전제가 깨지는 경우가 있다. 계약이 이걸 표현할 수 있나 |

**제안(결정 아님):** hint 없이 자체 association한 결과에는 낮은 신뢰도를 붙이거나
abstain하는 쪽으로 기울어 보인다. 다만 이 수치는 검출 박스만 쓴 바닥값이므로,
**결정은 span·사용자 단서를 쓰는 association을 한 번 재 본 뒤로 미룬다.**

## 4. 검출기 선택 — 왜 COCO `yolo11n`인가

association의 **상한**을 만드는 부분이라 기록해 둔다.

| 후보 | 판정 | 이유 |
| --- | --- | --- |
| `EasyKoreanLpDetector` (`lp_det.pt`) | ❌ | **번호판** 검출기다. 대상 차량을 못 찾는다 |
| `sauce_onnx` `plate_detect_v1` | ❌ | 같은 이유 |
| `yolov5` (레포만 있음) | ❌ | 가중치가 없다 |
| **Ultralytics `yolo11n` (COCO)** | ✅ | 이미 깔린 `ultralytics==8.4.133`로 바로 돈다 |

**파인튜닝 0.** 기준선의 정의가 「손대지 않은 상태」이고, 지금 학습을 시작하면 그건
Challenger다 — 로드맵이 P4 Go/No-Go까지 막아 둔 일이다.

파라미터: `conf=0.25` · `imgsz=640` · 매칭 `IoU ≥ 0.50` · COCO `car` `motorcycle`
`bus` `truck`. 라벨이 「정상 차량(**이륜차 포함**)」이라 `motorcycle`을 뺄 수 없다.
매칭은 confidence 내림차순 greedy이고, 자체 점검이 `--selfcheck`에 있다.

## 7. 이 데이터로 다음에 할 readout 실험

우선순위 순이다. 전부 readout 책임 8개 안에 있다.

1. **Overlay Timestamp OCR 기준선** (책임 ⑥⑦ · PR #81 직결) — **이 데이터에 overlay가
   찍혀 있다.** `INAVI QUANTUM 4K PRO` · `QXD3000MINI_S` · `V700` 등 **기기 모델이
   여러 종**이고 필드 구성도 다르다(전압만 / 전압+속도). 정답지는 화면에 있고, 클립당
   연속 프레임이 있어 **monotonic·duration 정합을 처음으로 실측할 수 있다.**
   부수 산출로 §6-① 라벨 감사가 따라온다
2. **클립 단위 표본으로 span association + 지속성** — §6-②⑦을 닫는다. 「프레임 선택
   전략(Best Frame / Multi-frame)」의 근거가 여기서 나온다
3. **무매칭 검출 50~100건 육안 검수** — §6-③이 닫힌다

### 범위 밖

- **번호판 검출·판독** — bbox 0건, 실물 10px대. 트랙 ②(블랙박스 수동라벨)가 소유한다
