# p3 기반 영상 판단 근거 진단과 프롬프트 실험

날짜: 2026-09-26. 범위: Search 내부 코드·테스트·문서. 사용자 승인 계획에 따라 `develop`의 `bae28184f9940c0da0bce3fe334a1432920bea97`에서 `feature/search-decision-trace`를 생성했다.

## 결정

- 미커밋 p4 구현을 폐기한다. 두 회차 실행 기록·조건·프롬프트 원문은 [종료 기록](../experiments/p4-retired-2026-09-25/conditions.md)에 보존한다.
- 운영 기본 프롬프트와 parser는 p3 그대로 둔다. `SearchService`, factory의 60초 예산, 공개 `search_candidates()`/`verify_visual()`, `CandidateEvent`/`VisualEvidence` 계약은 변경하지 않는다.
- 전용 로컬 실행기에서만 `p3`와 `diagnostic-v1`을 선택한다. 양쪽 모두 같은 미디어 준비와 provider 전송 경로를 사용한다. 진단 실행기는 공개 증거를 생성하지 않는다.
- `search-decision-trace/v1`은 **모델이 보고한 관찰과 결론 근거**를 저장한다. 비공개 사고 과정이나 검증된 영상 사실로 취급하지 않는다. Coarse 무후보 구간도 설명하고 Fine의 지지·반박 관찰과 한계를 받아 누락 원인을 조사한다.
- 진단 프롬프트는 기존 p3 지시문에 관찰 출력 지시만 덧붙인다. 첫 실험에서 검출 기준까지 동시에 바꾸지 않는다. 형식 정의와 실행은 [진단 가이드](../experiments/decision-trace-guide.md)가 소유한다.
- p3의 기본 형식 검증은 유지한다. 진단 설명의 확인 항목 누락·중복, 시간 초과는 고정 issue code로 기록하고 응답을 보존한다. p4의 중복 상태 필드·엄격한 의미 검증을 다시 도입하지 않는다. 자유 서술 모순은 사람 점검 대상으로 남긴다.
- 후보별 payload·API·미디어 오류는 원문 없이 고정 코드로 기록하고 다음 후보·영상을 계속한다. 단가 미설정이나 오류 호출의 사용량 누락을 0 비용으로 해석하지 않는다.

## 프롬프트 수정 실험 순서

1. **근거 가시화:** 같은 7영상으로 p3와 진단 형식을 각 1회 실행한다. 원본/준비 영상 해시, 템플릿·설정·코드 fingerprint, 시간 기준, 사용량, 실패를 기록한다. [정답지·관찰·판단 이유 비교](../experiments/seven-video-truth-observation-reason-2026-09-26.md)에서 Coarse·Fine 결과를 확인한다. 이 비교 문서는 기존 요약을 대체하며 사용자 승인으로 이번 실험의 AI 원문과 함께 저장소에 보관한다. 공유 가능한 실행 수치는 [결과 JSON](../experiments/decision-trace-seven-video-2026-09-26-results.json)에 보존한다.
2. **사람 검증:** 정답 구간의 실제 선 종류·차량·이동·침범 시각을 프레임으로 점검한다. 모델 설명을 정답으로 삼지 않는다. Coarse 누락, 시간 오인, 대상 오인, 선 종류 오인, Fine 판정 모순, 관찰 제한을 나눠 근거를 수집한다.
3. **한 변경씩 비교:** Coarse 시간 오인에는 절대 영상 시각과 주변 맥락 연결 지시를, 선 종류 오인에는 횡단 시점의 실제 선을 비교하는 지시를, Fine 결론 모순에는 관찰·반박·한계 요약 지시를 각각 별도 변형으로 실험한다. 입력과 설정을 고정하고 반복 횟수·순서를 먼저 정한다. 모델·fps·해상도 변경은 별도 실험으로 분리한다.
4. **오류가 남을 때 스키마 검토:** 프롬프트 변경으로 형식·의미 불일치가 반복되고 근거가 쌓이면 Search 내부 응답 스키마 간소화를 별도 결정으로 제안한다. 공개 계약 변경이 필요하면 해당 Owner 합의 후 진행한다.
5. **eval 합의 후 확대:** [#158](https://github.com/kakaotechcampus-4/ktc4-chonnam-2/issues/158)에 라벨·공식 시간 매칭·설명 groundedness·반복 정책·4종×15개 초기셋 기준을 요청했다. 답변 전에는 공동 성능 판정과 60영상 확장을 시작하지 않는다. 7개 단회 관찰은 채택 근거가 아니다.

## 보관과 전환

실행기는 전체 자유 서술을 Git 제외 `.superpowers/decision-trace/`에 저장하고 stdout에는 코드·상태·사용량·로컬 파일 경로만 출력한다. **2026-09-27 사용자 요청에 따라 이번 7영상의 상세 비교 문서, p3·진단 원응답 MD/JSON, 정답지 6개 파일은 `docs/modules/search/experiments/`에 함께 보관한다.** 모델 설명은 사람 검증 전 관찰 기록이며 공개 Search 증거가 아니다. 원본 영상·API 키·번호판·개인 식별 정보는 커밋하거나 이슈에 올리지 않는다. 후속 실행 원문은 로컬에 저장하며 저장소 포함은 별도 사용자 요청을 따른다.

p3 운영 기본값 전환은 이번 범위가 아니다. 채택은 평가 결과와 Search Owner 결정, 기존 [challenger 정책](challenger-policy.md)의 승인 경로를 따른다. eval 관련 새 기준은 합의 대기 상태로 유지한다.
