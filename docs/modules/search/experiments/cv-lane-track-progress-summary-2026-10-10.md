# CV_LANE_TRACK v1 — 진행 결과와 남은 작업

작성일: 2026-10-10 · 범위: 차량 모델 비교 → 차선 모델 비교 → 차량 추적 → 차선 교차 후보 → 후보 안정화 v2

## 1. 현재 결론

**모델을 실행해 속도와 출력 형태를 비교하고, 차량 추적과 차선 교차 후보 생성까지 연결했다. 정확도가 가장 좋은 모델과 최종 조합은 아직 선정하지 않았다.** 차량·차선·추적 정답 라벨(GT)이 없으므로 현재 수치만으로 검출 정확도, 사건 재현율, 실제 오탐률을 판단할 수 없다.

현재 연결한 조합은 **V1 AI Hub YOLOv5 차량 검출 + L3 UFLDv2 차선 검출 + ByteTrack/BoT-SORT 추적**이다. 실행 가능한 모델의 속도와 출력 관찰을 근거로 선택한 임시 조합이다. 차량 모델은 차량 위치를 찾고, 별도의 차선 모델이 차선 곡선을 찾는다. 추적기는 프레임 사이 같은 차량을 연결한다.

안정화 v2에서는 교차 후보가 **5건 → 2건**으로 줄었다. 남은 2건은 **C00 영상의 같은 시점 약 13.50초를 두 추적기가 각각 잡은 것**으로, 화면상 구간은 하나다. 후보는 모두 `UNKNOWN`이며 실선 차선 변경·중앙선 침범 등 실제 위반으로 확정한 결과는 없다. 보정 성공은 늘었지만 차선 연결은 줄어, 이번 변경을 종합적인 정확도·안정성 개선으로 채택하지 않았다.

**후속 1번 작업 완료:** [보정 선택과 차선 연결 개선](cv-crossing-continuity-2026-10-10.md)에서 유사 변환 우선·full 보완을 구현·검증했다. 보정 실패763→656, 연결 차선5,058→5,366, 새 차선ID2,687→2,379이며 C00 두 후보는 유지됐다. 입력 차선 오류와 정확도 미평가 상태는 남아 있다.

**2번 자료 준비 완료 / 정답 검수 대기:** [평가 라벨 준비](cv-label-preparation-2026-10-10.md)에서 원본1,200장·29작업의 자동 초안과 사건11건 검수표를 만들었다. 첫 검수 묶음은174장이다. bbox·차선·대상ID·실제 교차 시각은 아직 평가용 정답으로 확정하지 않았다.

## 3. 차량 모델 비교 결과

GPU는 RTX 3060 12GB, batch 1, CUDA FP32로 실행했다. 아래 시간은 모델별 공식 전처리·후처리를 포함한 **adapter 프레임 지연 시간**이다. 각 반복의 p50·p95를 구한 뒤 3회 값의 중앙값을 기록했다. p50은 중간값, p95는 느린 프레임까지 포함한 지연 수준이다.

| ID | 차량 검출 모델 | p50(ms/프레임) | p95(ms/프레임) |
| --- | --- | ---: | ---: |
| V1 | AI Hub YOLOv5 신호위반 모델의 차량 클래스 | 10.54 | 15.06 |
| V2 | AI Hub YOLOv5 중앙선침범 모델의 차량 클래스 | 11.93 | 15.98 |
| V3 | AI Hub YOLOv5 차선변경 모델의 차량 클래스 | 12.41 | 16.20 |
| V4 | YOLO11n | 13.62 | 19.53 |
| V5 | YOLO11s | 13.21 | 19.23 |
| V6 | YOLO26s | 14.57 | 21.63 |
| V7 | RT-DETR-L | 36.00 | 44.21 |

이 입력·설정에서 **V1이 가장 빨랐다.** 이름에 신호위반이 들어가지만 이번 단계에서 사용하는 출력은 차량 bbox(경계 상자)다. 이 모델 하나가 차선이나 위반까지 판정하는 구조는 아니다.

차량 bbox·동일 차량 ID·사건 대상 차량 라벨이 아직 없어 precision/recall·AP·원거리 차량 유지 성능을 계산하지 못했다. 작성된 GT 템플릿은 검수·라벨링 완료 상태가 아니며, 미확정 사건을 정상 사례로 취급하지 않았다. **V1을 가장 정확한 모델로 해석하면 안 된다.**

원래 계획의 신뢰도 임계값 보정, 상위 2종 선정, 상위 2종을 같은 ByteTrack으로 비교하는 과정은 미실행이다. 이를 한 번에 수행하는 전체 평가·선정 CLI와 상위 2종 추적 비교 runner도 아직 구현하지 않았다.

## 4. 차선 모델 비교 결과

| ID | 차선 모델 | p50 / p95(ms/프레임) | 실행 결과 |
| --- | --- | ---: | --- |
| L1 | AI Hub Mask R-CNN R50-FPN, 백색·황색 2개 모델 결합 | 195.45 / 305.14 | 3회 실행 완료 |
| L2 | CLRerNet⋆ DLA34 EMA | 미측정 | CUDA 빌드·Docker 실행 환경 문제로 추론 미실행 |
| L3 | UFLDv2 ResNet34 CULane | 51.42 / 90.30 | 3회 실행 완료 |

L3의 adapter p50은 L1의 두 모델 결합보다 약 **3.8배 빨랐다.** 전처리와 출력 구조가 다르므로 모델 자체 연산량의 공정한 비교나 정확도 우월성으로 확대 해석하지 않는다. L2는 소스·가중치를 확보했지만 CUDA 컴파일러 부재와 Docker 시작 실패로 막혔다. 성능이 낮아서 탈락한 모델이 아니다.

42개 시점을 14개 비교 시트로 확인했다. L1은 선이 조각나거나 겹치고 비현실적으로 연장되는 출력이 관찰됐다. 마스크를 곡선으로 변환하는 현재 방식은 연결 성분과 행별 중앙값을 쓰며, 원래 계획의 skeleton 방식은 아니다. L3는 더 길게 이어진 곡선을 출력하지만 차량 차체·보닛·와이퍼를 관통하거나 가림 구간에서 잘못 이어지고 교차로 차선을 놓치는 문제가 있었다.

빈 차선 출력은 L1 1/1,200, L3 96/1,200이었다. 정답이 없고 출력 단위도 다르므로 이 숫자는 차선 누락률·recall이 아니다.

**L3는 차선 위치 곡선만 제공한다.** 현재 출력에는 신뢰도, 백색·황색, 실선·점선, 중앙선 역할이 없다. 신뢰도는 `null`, 의미는 `UNKNOWN`으로 저장하며 시각화 색상은 선을 구분하는 표시다. 최종 모델 선정과 차선 유형 판별은 남아 있다.

## 5. 차량 추적과 최초 교차 후보

V1·L3로 전체 15개 영상을 한 번 처리하고, 같은 V1 검출 캐시를 두 추적기에 입력했다. 신뢰도 임계값 0.25는 GT로 보정한 값이 아니다. BoT-SORT는 ReID를 끄고 sparse optical flow 기반 카메라 보정을 사용했다.

| 추적기 | 추적 단계 p50 / p95(ms/프레임) | 출력 관측 수 | 영상별 차량 ID 수의 합 |
| --- | ---: | ---: | ---: |
| ByteTrack | 1.96 / 3.34 | 16,558 | 595 |
| BoT-SORT | 8.14 / 25.68 | 16,693 | 682 |

ByteTrack이 이 설정에서 더 빨랐다. 관측 수·ID 개수·관측 간격은 진단 수치이며 실제 ID 전환 횟수나 추적 정확도를 뜻하지 않는다. 육안으로는 V1의 중복 bbox, 보행자를 차량으로 잡은 사례, 흐린 장면의 차량 관측 공백과 L3의 잘못된 곡선을 확인했다.

최초 교차 단계는 **현재 검출 bbox의 아래쪽 중앙점을 차량 접지의 대리점**으로 사용했다. 이 점과 같은 높이의 차선 사이 거리 부호가 바뀌고 일정 시간 유지되면 후보를 만들었다. 실제 타이어 접지는 라벨링하지 않았고, 추적기의 예측 bbox만 남은 프레임은 접지 관측으로 사용하지 않았다.

최초 결과는 ByteTrack 2건·BoT-SORT 3건, 총 5건으로 화면상 C00·C33·C10의 3개 구간이었다. 두 추적기가 같은 사건을 잡으면 각각의 진단 후보로 남기므로 후보 개수와 실제 사건 개수는 다르다. 차선 신뢰도·유형이 없어 점수와 위반 유형을 만들지 않았고 Top-K 순위도 매기지 않았다.

## 6. 최신 안정화 v2 결과

같은 영상·모델·추적 캐시를 고정하고 다음 세 가지를 함께 바꿨다.

1. 카메라 보정을 partial affine에서 full affine으로 변경하고 변환 품질 조건을 유지했다.
2. 밝기 변화가 커도 기하 보정과 정규화된 영상 상관도가 충분하면 기존 상태를 이어 갔다.
3. 너무 작거나 화면 경계에 걸린 차량 bbox는 교차 판단용 접지 관측을 보류했다. 해당 차량 출력은 계속 저장·표시하고, 보류 구간을 건너 상태를 연결하지 않았다.

| 카메라 보정 성공 프레임 | 2,431 | 2,451 | 순증 20프레임 |
| 보정 실패 프레임 | 782 | 763 | 실패 일부 감소 |

기존 실패 중 128프레임은 보정에 성공했지만, 기존 성공 중 109프레임은 새로 실패했다. 장면 전환 1프레임의 상태 유지까지 포함해 성공 수가 20 늘어난 것이다. 모든 영상에서 고르게 개선된 결과는 아니다.

| 구간 | 최초 후보 | v2 결과 | 현재 판단 |

| C00 약 13.50초 | 두 추적기에서 발생 | 두 추적기 모두 유지, 후보 창 약 11.50–15.50초 | 화면상 흰색 차량의 횡이동은 보이지만 실제 차선 교차·위반 GT는 없음 |
| C33 약 13.09초 | 두 추적기에서 발생 | 경계 bbox 관측 보류로 후보 없음 | 확정 오탐 제거가 아니라 불확실 관측 보류 |

640×360 입력에서 폭 32px 미만 또는 높이 18px 미만의 bbox는 작은 관측으로 보류하며, 경계 여유는 가로 4px·세로 2px다. 원본 크기에 비례하는 규칙이므로 작은 차량 보류가 원거리 탐지 성능에 주는 영향을 평가해야 한다.

C47 약 48초의 밝기 변화는 상태를 유지했다. 나머지 4개 reset 시점은 연속 주행 중 조명 변화였지만 필요한 기하 품질을 확보하지 못해 보호용 reset을 유지했다. 차량 차체·와이퍼를 따라가는 차선, 교차로 누락, 짧은 차선 교체 문제도 남았다.

검증 기록은 **테스트 25개 통과, 출력 영상 32개 전체 decode, 이미지 55장·원본 시점 159개 육안 확인**이다. 출력 형식·상태 전이·보류 구간 연결 방지·원본 보존을 검증한 것이며, GT 정확도 검증은 아니다. 이 정리 문서를 작성하면서 모델 실행이나 위 테스트를 다시 수행하지는 않았다.

## 7. 남은 작업과 권장 순서

출력 개선과 정답 평가를 구분해 진행한다. **1번의 보정 선택 구현·원인별 비교·원거리 보류 영향 진단은 후속 실험에서 완료했다.** 남은 보정 실패와 입력 차선 오류는 잔여 과제다. 최종 모델 선정에 필요한 GT 준비는 병행할 수 있다.

1번의 잔여 보정 실패·입력 차선 오류는 기존 출력으로 추가 진단할 수 있다. 다만 개선됐다는 정확도 결론은 GT 평가가 있어야 한다. 6번의 C0–C5는 최초 계획의 정식 누적 비교이며, 최초 결과 대 v2 비교나 후속8조합의 효과 분리 실험으로 대체할 수 없다. v2의 세 변경 효과는 후속1번 실험에서 분리해 확인했다. 유형·점수 처리와 평가 도구는 정식 규칙 비교 전에 준비해야 한다.

정상 113개 영상은 원래 계획에서 파일 미확보로 기록됐다. 이번 문서 작성 시 `eval/manifests/b_youtube/clips.json`의 **전체 123개 항목 중 지정된 파일 경로에 실제 파일이 존재하는 것은 0개**였다. 123개 모두가 정상 영상이라는 뜻은 아니다. 정상 113개 대상 목록과 실제 데이터 확보를 별도로 확인해야 한다.

현재 개발 사건은 **차선 관련 11건(실선 변경9건·중앙선2건, 선 색상은 추가 검수 필요)**이며 신호위반 2건은 이 평가 분모에서 제외한다. 후보 2건을 11건과 단순히 나눠 recall로 계산할 수 없다. 사건 대상 차량과 실제 교차를 맞췄는지 확인해야 한다.

조건을 확정한 뒤 정상·독립 검증 데이터를 평가해야 한다. 모든 15개 개발 영상과 후속 예측을 이미 관찰했으므로 지금 만드는 GT를 과거의 ‘예측을 보기 전에 작성한 독립 GT’라고 기록할 수 없다.

## 8. 라벨링과 사용자 준비 사항

**기존 출력으로 다음 개선 작업을 시작하는 데 추가 라벨링이 필수는 아니다.** 속도 측정, 출력 비교, 실패 구간 진단, 교차 후보 생성은 지금 데이터로 계속할 수 있다.

**어떤 모델이 가장 정확한지, 실제 사건을 얼마나 놓치는지 결론 내려면 검수된 라벨이 필요하다.** 모델 재학습을 위한 라벨링이 아니라 평가용 정답 작성이다. 자동 초안을 활용하더라도 차량·차선·사건의 정답 검수는 필요하며, 사용자가 모든 프레임을 직접 그려야 한다는 뜻은 아니다.

| 목적 | 필요한 라벨 | 현재 상황 |
| --- | --- | --- |
| 차량 정확도 | 비교 프레임의 전체 차량 bbox, 제외 영역·라벨 완료 여부 | 원본1fps651장·자동 초안 준비, 미검수 |
| 차량 추적·사건 대상 평가 | 프레임 간 같은 차량 ID, 가림·진입·이탈, 사건 대상 차량 | 5fps549장·ID입력 항목 준비, 정답 미확정 |
| 차선 정확도·위반 유형 평가 | 차선 곡선, 가시성, 실선/점선, 색상, 중앙선 역할 | 곡선 초안·속성입력 항목 준비, 정답 미확정 |
| 후보 적중·시각 평가 | 실제 교차 시각, 대상 차량·차선, 실제 장면 전환 | 사건11건 검수표 준비, 정밀시각 미확정 |
| 정상 후보 발생량 | 정상 대상 목록과 실제 영상, 정상 여부 확인 | 영상 확보 필요 |

일부 대표 구간부터 라벨을 만들면 소규모 진단은 가능하다. 전체 모델 순위나 전체 precision/recall을 주장할 때는 평가 범위의 라벨 완성도를 충족해야 한다. 현재 사용자가 준비할 핵심 자료는 **원본 정답을 확인할 수 있는 사건 정보와 정상·독립 검증 영상**이다. 학습이나 모든 모델 재실행은 이번 정리의 필수 작업이 아니다.

Fine 단계 연결, #283·#325 반영, 운영 Search 통합·배포는 후속 별도 범위다. 현재 결과로 바로 운영 위반 판정을 적용하는 단계까지 완료한 것은 아니다.
