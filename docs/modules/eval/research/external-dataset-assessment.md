# 외부 공개 데이터셋 3건 — 평가셋 사용 가부 조사

> **이 문서가 하는 일.** B tier 소스를 유튜브에서 외부 공개 데이터셋으로 바꿀 수 있는지 조사한 결과를 남긴다. `eval-dataset-plan.md` §6-2(라이선스 근거 미결)가 남겨둔 「공개 데이터셋」 선택지를 실제 후보로 검토한 기록이다.
> **결정 문서가 아니다.** 현행 manifest·정답지의 authoritative source는 `eval/manifests/`다. 이 문서는 후보를 줄였을 뿐 §6-2를 닫지 않는다.
> **Owner:** 김대원(`eval`) · 작성 2026-09-16

## 3. 핵심 발견 — 공개 데이터셋에는 정상 주행이 없다

| | 국내 도로 | 위반/사건 라벨 | **정상 주행 대량** | 번호판 |
| --- | --- | --- | --- | --- |
| AI-Hub 628 | O | 차로 위반 1종만 | **X** | 비식별 |
| AI-Hub 597 | O | 과실비율(위반 유형 아님) | **X** — 사고만 | 미확인 |
| D²-City | **X** (중국) | 없음 | **O** | 블러 |
| 현행 B tier (YouTube) | O | 우리가 라벨링 | **O** | (B tier 미측정 지표) |

국내 공개 데이터셋은 전부 **위반·사고만 모아두었다.** 이는 A tier가 전 시퀀스 4종 중 하나여서 `NONE` 클래스를 자체적으로 못 채우는 것과(`harness-v1-design.md` §4-2) 정확히 같은 구조다. 공공 데이터 구축 사업은 관심 사건을 모으는 것이 목적이므로 정상 주행은 애초에 수집 대상이 아니다.

`fp_per_clip`의 분모는 「봤고 위반 없음」 클립이다. 그 분모를 대량으로 제공하는 소스는 **무편집 연속 실주행 영상뿐**이고, 그래서 유튜브 B tier는 타협이 아니라 구조적으로 유일한 선택이었다. `eval-dataset-plan.md` §2-1이 「사고 모음집을 쓰면 `fp_per_clip`이 실제보다 좋게 나온다」고 경계한 논리가 공개 데이터셋 전반에 그대로 적용된다.

## 4. 후보별 기각 사유

### 4-1. D²-City — 도메인 타당성

**기각 사유가 아닌 것을 먼저 분리한다.**

- **위반 라벨 부재는 기각 사유가 아니다.** `violation_type`·`t_onset_sec`·`target_vehicle`·`scoring`은 유튜브 클립에도 우리가 직접 붙인다. 라벨링 비용은 **동률**이다.
- **번호판·타임스탬프 블러도 B tier 판단에서는 무관하다.** Plate 3종(`exact_plate_accuracy`·`wrong_accept_rate`·`abstention_recall`)과 time 2종(`time_accuracy`·`unknown_rate`)은 `eval-dataset-plan.md` §1에서 **C tier 몫**이다. B tier가 지는 지표에는 번호판 문자도 화면 타임스탬프도 필요하지 않다. 단 이 블러 때문에 **D²-City를 C tier 대체 후보로 쓰는 길은 영구히 막힌다** — A tier가 막힌 것과 같은 이유다(`harness-v1-design.md` §4-3).

**실제 기각 사유는 도메인 타당성이다.** 라벨링을 아무리 엄격하게 해도 결과물은 *중국 도로를 한국 도로교통법 기준으로 판정한 측정치*다. 우측통행·황색 중앙선처럼 겹치는 부분이 있어 「대충 비슷하다」고 넘기기 쉬운데, 신호등 구성·우회전 규칙·노면표시 체계가 달라 라벨러가 기준을 일관되게 적용하기 어렵다. `eval-dataset-plan.md` §4는 「혼자 라벨링하므로 기준이 시간에 따라 흔들릴 위험이 크다」고 적었는데, 낯선 도로 규칙은 그 위험을 키우는 쪽이다.

특히 `MOTORCYCLE_HELMET_NON_USE`는 이륜차 구성 자체가 다르다. D²-City가 객체 클래스에 `open-tricycle`·`closed-tricycle`을 따로 둘 정도다.

`eval-dataset-plan.md` §2-2 [필수] 「국내 도로 우선 — 신호체계·중앙선·차선 규칙이 다르면 라벨 기준이 흔들린다」가 이 경우를 그대로 가리킨다.

**부수 사유 — 클립 구조.** 30초 고정이고 같은 차량의 연속 클립을 배제해 뽑았으므로 §3-1의 「1시간 원본 → 60개 1분 클립, 겹침 없는 연속」 구조를 만들 수 없다. 원본 시간축이 없어 §4-2의 경계 사건 쌍(클립 07/08 구조)도 생기지 않는다.

**출처 신뢰성과 구성 타당성의 맞교환.** D²-City는 DOI·논문·명시된 배포 경로를 갖춰 *출처* 신뢰성은 유튜브보다 확실히 높다. 그러나 그 숫자가 「우리 제품이 한국 도로에서 얼마나 하는가」를 말해주는 정도는 *내려간다.* 신뢰성 문제를 더 나쁜 신뢰성 문제와 바꾸는 거래다.

### 4-2. AI-Hub 628 — 커버리지와 입력 형태

- **위반 유형 커버리지가 1/4다.** 「위반 여부」 라벨은 차로 위반 하나이고, baseline enum 4종 중 `SOLID_LINE_LANE_CHANGE` 계열에만 대응한다. `SIGNAL`·`CENTER_LINE_CROSSING`·`MOTORCYCLE_HELMET_NON_USE`는 없다.
- **초당 5프레임**은 실서비스 입력 형태와 다르다. 원천데이터가 JPG 프레임이라 성격이 A tier에 가까워지고, B tier가 재려던 「연속 영상에서 사건을 찾는 능력」을 재지 못한다.
- **번호판 비식별** — C tier 대체 불가(A tier·D²-City와 동일).
- **정상 주행이 없다**(§3).

**부분 인용은 가능하다.** 차로 위반 판정 기준을 국내 공공 데이터 구축 사업이 어떻게 정의했는지를 우리 라벨링 규칙서(`eval-dataset-plan.md` §4, 미작성)의 근거로 인용할 수 있다. 데이터를 쓰는 것과는 별개다.

### 4-3. AI-Hub 597 — base rate와 라벨 축

- **사고 데이터다.** `eval-dataset-plan.md` §2-1이 「사고·위반 모음집」을 명시적으로 제외한 이유가 그대로 적용된다. 오탐을 셀 정상 클립이 없어 `fp_per_clip`이 실제보다 좋게 나온다.
- **라벨 축이 다르다.** 과실비율(0~100)은 사고 책임 배분이고 우리가 재는 위반 유형 분류가 아니다. 둘 사이의 변환 규칙은 존재하지 않는다.
- 블랙박스 원본(`bb`)이 들어 있다는 점과 날씨 메타가 있다는 점은 매력적이지만 위 둘을 상쇄하지 못한다.

## 5. D²-City 제한적 활용안 — `fp_per_clip` 보조 tier

국내 후보들이 못 주는 「정상 주행 대량 + 조건 다양」을 주는 유일한 데이터셋이라는 점은 §3 표에 남는다. 활용한다면 **정상 주행 negative 풀** 용도에 한정한다.

**이 용도가 성립하는 이유.** 「봤고 위반 없음」 확인은 위반 유형 판정보다 도로 규칙 차이의 영향을 덜 받는다. §4-1의 도메인 문제가 가장 약해지는 지점이다. 라벨링 비용도 낮다.

**조건 3가지.**

1. 별도 `source_tier` 값으로 표시해 결과 파일이 스스로 출처를 말하게 한다(`harness-v1-design.md` §4-2의 `source_tier` 도입 근거와 동일).
2. 한국 도로 지표와 **절대 합산하지 않는다.**
3. 헤드라인 recall 숫자에 넣지 않는다. `fp_per_clip`과 조건 강건성 관찰용으로만 읽는다.

**착수 전 확인.** §7-4의 라이선스·배포 경로가 먼저 닫혀야 한다. 100시간 규모의 다운로드·스토리지 비용도 산정이 필요하다.

## 6. B tier 신뢰성 문제의 실제 해법

이 조사의 출발점은 「유튜브는 신뢰성·근거가 약하다」였다. 실제 약점은 둘이고, **둘 다 소스 교체와 무관하다.**

1. **출처 기록 누락** — `clips.json`에 `source_url`·`license`가 없다(`eval-dataset-plan.md` §8-4). 데이터 문제가 아니라 기록 문제이고, 원본 YouTube URL과 라이선스 표기를 manifest에 채우면 닫힌다. §6-2의 라이선스 근거는 「CC BY 영상 / 업로더 허락」 쪽으로도 닫을 수 있다.
2. **원본 편수 부족** — 현재 3편(`YT_0001`·`0002`·`0003`, 123클립, split 전부 DEV). 조건 다양성(§2-3)과 group 분리(§3-2)가 검증되지 않았고 `locked` split이 없다. 무편집 연속 주행 영상을 **더 모으는 것**이 직접 해법이다.

보조로, AI-Hub 628의 위반 판정 기준을 라벨링 규칙서의 근거로 인용하면 「국내 공공 데이터셋도 같은 기준으로 라벨링한다」는 근거가 생긴다(§4-2).

## 7. 미결

- **7-1 AI-Hub 628 원시 MP4 배포 여부(김대원).** 페이지는 원시데이터를 "MP4 포맷의 동영상 클립"으로 적었지만 실제 배포 패키지에 원천 JPG만 들어 있을 수 있다. 신청 후 확인한다.
- **7-2 AI-Hub 597 번호판 비식별 여부(김대원).** 페이지에 명시가 없다. 628과 달리 비식별 문구가 보이지 않는데, 처리를 안 했다는 뜻인지 표기 누락인지 확인되지 않았다.
- **7-3 두 AI-Hub 데이터셋의 평가 목적 사용 가부(김대원).** 이용정책상 「사용 목적 등이 부적합하다고 판단될 경우 제공이 거부」된다. 학습이 아닌 평가 용도가 승인되는지 확인 필요.
- **7-4 D²-City 라이선스 표기와 배포 경로(김대원).** ScienceDB 상세 페이지가 SPA라 본문을 읽지 못했고 API도 응답하지 않았다. "Research Only" 표기는 2차 출처에서 확인한 것이고, DiDi outreach 배포 경로가 현재 살아 있는지도 확인하지 않았다.
- **7-5 `eval-dataset-plan.md` §6-2는 여전히 미결이다.** 이 문서는 「공개 데이터셋」 선택지의 후보를 줄였을 뿐 라이선스 근거를 확정하지 않는다.
