# 장면 찾기 세부 안내 — 로컬 구현

- 준비: 원형 회전 + `영상을 준비하고 있어요`.
- 탐색: 1/3 원형 + `말씀하신 상황을 찾고 있어요`.
- 정리: 2/3 원형 + `찾은 장면을 정리하고 있어요`.
- 완료: 기존 체크 + `장면 찾기를 마쳤어요`.

원형은 세 작업 중 완료된 작업 수다. 시간 비율·남은 시간·AI 응답 내부 진행률이 아니다. 실제 Search 경계에서만 바뀌므로 빠른 정리 단계는 2초 폴링 사이에 지나갈 수 있다. 보여주기 위해 처리를 늦추지 않는다.

진행 안내는 한 줄 영역에 들여쓰고 글자 안에서 밝기가 흐른다. 완료 안내는 밝은 글자와 약한 테두리 강조를 쓴다. 좁은 화면에서는 줄바꿈을 허용하며 reduced-motion에서는 모션을 제거한다.

`SEARCHING` 최초 진입 후 120초가 지나면 `장면을 찾는 데 시간이 더 걸리고 있어요`로 바뀌어 다음 단계까지 유지한다. 이 값은 UX 임시 기준이며 서버의 150초 실행 예산·180초 대기 마감은 바꾸지 않는다. 준비 시간은 이 120초에 포함하지 않는다. 서버 시각을 사용하므로 새로고침과 자동 재시도에도 탐색 시간이 초기화되지 않는다.

Worker는 Recording 준비 전과 Search의 준비·탐색·정리 경계를 Case에 보고한다. Case는 현재 job, 최신 RUNNING execution, 대기 마감을 확인한 뒤 기존 `cases.state` JSON에 저장한다(별도 DB migration 없음). 표시 기록 실패는 분석을 실패시키지 않고 정제된 로그만 남긴다. API·Worker·Web을 함께 적용해야 실제 세부 단계가 연결된다. 구버전 API는 기존 회전 표시와 일반 안내로 표시한다.

실패·시간 초과·사용자 중단은 기존 화면과 `RETRY_SEARCH` 동작을 사용한다. 자동 재시도는 같은 job의 완료한 단계와 시각을 유지하고, 사용자의 새 탐색은 새 job으로 초기화한다. 모션 자체는 서버가 정상 작동한다는 증명이 아니다.

API 진행 조회가 무응답·연결 오류로 실패하면 마지막 진행 화면을 내리고 `진행 상태를 확인할 수 없어요`를 보인다. 분석 실패나 종료로 단정하지 않는다. JSON 요청의 기존 제한은 15초이며, 실패 후 2초 간격으로 GET 조회만 재시도한다(각 요청 완료 후 간격). 연결이 복구되면 최신 CaseView로 돌아간다. 조회 실패 중에는 command를 다시 보내지 않는다. 최초 이어받기 조회 실패에도 같은 정책을 적용하며, 404는 재조회하지 않는다.

재조회 중에는 `연결을 다시 확인하고 있어요` 앞에 기존 16px 회전 원을 두고, 아래에 `연결되면 최신 진행 상황을 자동으로 보여드릴게요.`를 보조 글자색으로 표시한다. 글자는 움직이지 않는다. 원은 연결 확인 동작을 알리며 분석 진행률을 의미하지 않는다. 404에는 모션을 붙이지 않고, reduced-motion에서는 원의 회전도 멈춘다.
