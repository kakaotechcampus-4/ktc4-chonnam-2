# Intent Hint 평가용 실사용자급 문장 수집 — 준비만 해둔 계획 (실행 전)

> 작성일 2026-09-22 · 담당 유소연(`case`) · **결정 문서 아님 — 실행 여부·시점은 별도 결정**
> 배경: `decisions/intent-llm-model-selection.md` §8·`decisions/intent-llm-eval-target-thresholds.md` §1의 표본 크기(N) 미결 항목. `research/intent-llm-robustness-test-design.md` §12-B에서 이 문서를 가리킴.

## 1. 왜 "진짜 로그"가 아니라 설문인가

`datasets/intent-hint-eval-v1.jsonl`(7케이스)·`intent-hint-robustness-v1.jsonl`(27케이스)은 전부 case 담당자 본인 또는 AI 도구가 만든 예시문이다. 같은 저자(들)가 만들다 보니 표현 패턴이 비슷해질 위험이 있다 — 이게 표본 크기(n) 문제와는 별개로 존재하는 **다양성 문제**다.

case가 아직 런칭 전이라 실제 사용자 로그는 없다. 대신 **case 담당자·AI가 아닌 실제 다른 사람**이 자유롭게 쓴 문장을 모으면, 진짜 로그는 아니어도 "같은 저자 편향"은 없앨 수 있다. 이게 이 계획의 목적이다 — 표본 크기(N)를 실제 사용 데이터로 늘리는 것의 완전한 대체재는 아니고, 런칭 전 임시 보완책이다.

## 2. 수집 대상·규모

- 팀 6명 + 팀 밖 지인 포함, **목표 15~20명**. 같은 사람이 여러 문장을 써도 되지만 사람 수 자체를 늘리는 걸 우선한다(저자 다양성이 핵심 목적이므로).
- 응답자에게 지금 있는 카테고리 이름(무관한 질문/모순 정보 등)을 미리 알려주지 않는다 — 알려주면 그 틀에 맞춰 쓰게 돼 자유도가 떨어진다.

## 3. 설문 문항 초안 (그대로 구글폼 등에 옮기면 됨)

**안내문(설문 맨 위에 그대로 붙이기):**
> 블랙박스 영상 기반 교통위반 신고 서비스를 테스트하기 위한 문장을 모으고 있습니다. 실제 있었던 일이 아니어도 되고, 상상해서 자유롭게 써주시면 됩니다. **다만 실제 차량 번호판, 실명, 정확한 자택 주소처럼 특정인을 식별할 수 있는 정보는 적지 말아주세요** — 가상의 상황으로 써주세요.

- **Q1(필수).** 블랙박스 영상 속에서 교통법규를 위반한 차량을 봤다고 가정하고, 지금 막 신고 앱에 그 상황을 입력하려고 합니다. 어떻게 쓰시겠어요? 1~2문장으로 편하게 적어주세요.
- **Q2(선택).** 이번엔 좀 더 급하게, 문자 보내듯 짧게 써주세요.
- **Q3(선택).** 이번엔 시간이나 장소가 잘 기억나지 않는 상황이라고 가정하고 써주세요.
- **Q4(선택).** 하고 싶은 말이 있으면 자유롭게(형식 제약 없음).

Q2~Q4는 응답자에게 "이런 카테고리를 채워달라"고 설명하지 않고 자연스럽게 다른 화법(급함/모호함/자유형식)을 끌어내려는 의도다 — 문항 자체엔 그 의도를 안 드러낸다.

## 4. 수집 후 통합 절차 (아직 실행 안 함)

1. **PII 스크럽(사람이 직접 확인)** — 응답 중 실제 식별정보가 섞여 들어왔으면(안내했어도 실수로 쓸 수 있음) 그 응답은 통째로 제외하거나 식별정보만 가상값으로 바꾼다. 이 단계를 건너뛰고 저장소에 올리지 않는다.
2. **`expected_notes`는 사람이 직접 쓴다** — LLM에게 채점 기준을 대신 만들게 하지 않는다(이 데이터로 LLM들을 비교하는 게 목적이라, 정답지 자체를 LLM이 만들면 순환 검증이 된다). `datasets/intent-hint-eval-v1.jsonl`·`intent-hint-robustness-v1.jsonl`과 같은 방식 — 문장에 실제로 있는 값이 뭔지 사람이 읽고 판단해서 적는다.
3. **`scenario_tag`는 기존 카테고리에 억지로 끼워 맞추지 않는다** — 내용이 맞는 기존 카테고리(예: 시간 애매)에 속하면 그 태그를 쓰고, 안 맞으면 새 태그(예: `실사용자_문장`)를 쓴다. 새 카테고리가 나오면 그 자체로 발견이니 `research/intent-llm-robustness-test-design.md`에 추가한다.
4. **별도 파일로 저장** — `datasets/intent-hint-eval-v2-real-text.jsonl`(가칭). 기존 `intent-hint-eval-v1.jsonl`/`intent-hint-robustness-v2.jsonl`을 덮어쓰지 않는다(Locked Dataset 정책 그대로 — README 참고). id 접두사는 `case-r01`처럼 구분해서, 나중에 "합성 데이터 vs 실사용자급 데이터" 결과를 나눠 볼 수 있게 한다.
5. **하네스 실행** — 새 파일이라 `runner.py --dataset ... --out ...`으로 기존 후보 4개(GPT-5 Nano/Gemini 3.1 Flash-Lite/Claude Haiku 4.5/Gemini 3.8 Flash)에 그대로 돌릴 수 있다. 코드 변경 불필요.

## 5. 아직 정하지 않은 것

- 실제로 언제 설문을 돌릴지(지금 진행 중인 강건성 데이터셋 확장과 동시에 할지, 그 이후로 미룰지)
- 목표 응답 수(15~20명은 잠정치, 실제로는 응답률에 따라 달라질 수 있음)
- PII 스크럽을 case 담당자 혼자 할지, 리뷰어를 한 명 더 둘지
