# Correction 로그 재사용 정책 — 전제 「재사용 한다」와 익명화 규칙

> 결정일 2026-09-04 · 근거 `management/cross-cutting-decisions.md` C-4 · §3-(2)
> **담당:** 유소연(`case`) · **Consulted:** 정철원(`recording` — 보관·삭제 실태) · 김준영(마스킹 로거 + Product Spec 승인)

## 결정된 것

**정책 전제: 사용자 correction 데이터를 재사용한다.** 실제 서비스 운영 시나리오를 산정하는 것이 이 프로젝트의 목적 중 하나이므로, 재사용을 전제로 동의 · 익명화 · 철회 · 보관을 전부 설계한다.

**재사용은 두 단계로 나눈다 — 동의 수준이 다르다.**

| 단계 | 무엇에 쓰나 | 경로 | 10주 내 |
| --- | --- | --- | --- |
| **1단계 — 평가 재사용** | 팀이 채점 · hard-negative 후보 · 실패 통계에 쓴다 | `case.export_learning_log()` → 익명화 파일 → `eval` (`module-architecture.md` §9-5) | **구현** |
| **2단계 — 학습 재사용** | 모델 fine-tuning 학습 데이터 | 없음. §10-3 `[미결 유지]`의 fine-tuning과 연결 | 전제만 |

고지 문구는 처음부터 두 단계를 구분해서 쓴다. 한 줄로 뭉뚱그리면 2단계를 열 때 동의를 다시 받아야 한다.

## 익명화 최소 규칙 (v3 §9-4에서 복원)

`export_learning_log()`가 내보내는 파일은 최소한 다음을 지킨다. 구체 필드는 Data Contract(`CorrectionRecord`)에서 확정하되, 이 3줄보다 약해지지 않는다.

```text
· 번호판 문자열 제거 — 틀린 위치와 문자 개수만 남긴다
· 정확한 좌표 제거 — 오차 반경만 남긴다
· 원본 영상 참조는 로컬 케이스 ID로만 — 파일 경로·파일명·외부 provider ref를 넣지 않는다
```

사건 단위 학습 이력을 위해 correction이 어떤 `selection_rev` / candidate context에서 발생했는지는 보존한다(§9-5).

## `case` Owner가 설계할 것 (초안 → PM 승인, Product Spec 변경 절차)

| # | 항목 | 상태 |
| --- | --- | --- |
| 1 | 동의 문구 + **동의 상태를 어디에 저장하나** (`Case`? 사용자 계정?) | 미결 |
| 2 | 익명화 수준 — 위 3줄을 `CorrectionRecord` 필드로 | 미결 |
| 3 | correction 로그의 **보관기간** — 원본 영상과 수명이 다르다. 「영상은 지웠는데 로그는 남는 상태」를 정의한다 | 미결 |
| 4 | **철회(동의 취소) 시 이미 내보낸 로그를 어떻게 하나** — 파일로 나간 뒤라 되돌리기 어렵다 | 미결 |
| 5 | 1단계 / 2단계를 구분한 고지 문구 | 미결 |

## 소유 경계

| 무엇 | 소유 |
