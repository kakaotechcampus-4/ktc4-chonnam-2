# KTC Pitch Notes — 1.3 Snapshot

> 서비스 기획안 1.3의 발표용 부분을 archive로 분리했다. 현재 Product Spec을 대신하지 않는다.

## 2분 피치 골격

**누구의 어떤 문제 → 실제 어떻게 준비하는지 → 기존 대안(신고콕)과 남은 gap → 우리 흐름 → 왜 Agent인지 → 3개월 뒤 남는 것 → 첫 사용자 채널**

### 누구의 어떤 문제

> 박신고 씨는 위험한 교통위반을 봤고 이미 신고하려고 마음먹었다. 하지만 집에 돌아와 SD카드를 연결한 뒤 사건 파일부터 다시 찾고, 구간·용량·시간·위치·차량번호를 맞춰야 한다.

### 지금 어떻게 버티는지

> 실제 신고 workflow에서도 SD카드 영상탐색 → 편집파일 첨부 → 안전신문고 위치 검색/핀조정 → 차량번호·날짜·시간·내용 → 본인인증을 거친다. 신고콕은 이 후반부를 줄이지만 사용자가 사건을 먼저 찾아야 한다.

### 우리 흐름

> `6시 반쯤 흰 SUV가 실선을 넘었어요`라고 말하면 기억단서를 정리하고, 장시간 영상에서 Top-3와 시각적 근거를 찾는다. 사용자가 사건을 고르면 번호판·시각출처·위치단서·신고영상을 구조화해 SafetyReport handoff까지 준비한다.

### 왜 챗봇이 아닌지

> 대화는 navigation이다. 실제로는 Long-video VLM·OCR·metadata/GPS·FFmpeg·Evidence Rule을 Case State에 따라 호출하고, 중요한 결과는 structured card에서 사람이 검증한다.

### 3개월 뒤 남는 것

> 특정 모델보다 locked real long-dashcam eval/failure/correction data와 Agentic Evidence workflow를 남긴다.

### 첫 사용자 채널

> 보배드림 교통사고/블랙박스 게시판에서 실제 신고 행동 인터뷰부터 Prototype 비교까지 이어간다.

### 심사위원 머리에 남길 한 장면

> 수십 개 블랙박스 파일 + `6시 반쯤 흰 SUV가 실선을 넘었어` → Top-3 Candidate → 사용자가 한 장면 선택 → 20초 Evidence clip + plate best frame + time/location provenance가 한 카드로 정리되는 순간

## 숫자를 말할 때의 규율

- 366만 건 / 203만 건 등 조사값과 20→3분 목표가설을 구분한다.
- 20분은 평균으로 말하지 않는다.
- 57만 시간은 potential impact estimation으로만 말한다.
- 실측 전 90% 정확도나 3분 완료를 주장하지 않는다.

## 당시 마지막 불확실성

> Evidence Preparation 중 사건 재탐색이 실제 신고자의 최우선 pain인지, 자동 준비가 실제 신고 완료 행동을 얼마나 높이는지, real long-dashcam에서 초기 4종 event를 감당 가능한 비용·지연으로 Final Top-3에 안정적으로 넣을 수 있는가.
