01 — 1차 시안에서 바뀐 것

직관성을 떨어뜨린 원인부터 걷어냈다

항목1차 시안이번이유
표면 어두운 작업공간 #141A21 밝은 #f7f9fc + 흰 패널 어두운 UI가 "AI 도구" 인상을 만들었다. 영상은 프레임 안에서만 어둡다.

상태 표현 얇은 테두리 칩 (색 위주) 배지 = 색 + 점 + 아이콘 + 라벨 색만으로 구분하면 색각 이상·흑백에서 무너진다. 점 + 아이콘 + 라벨을 항상 함께 둔다.
작업 상태 정보 상태와 같은 칩 사용 진행 목록 전용 컴포넌트 Core Flow §3이 금지한 혼용이었다. 이제 컴포넌트 자체가 다르다.
제출 방식 복사 버튼 하나로 뭉뚱그림 붙여넣기 3 / 직접 선택 4로 분리 안전신문고에서 붙여넣을 수 있는 칸은 제목·신고 내용·차량번호뿐이다. 발생일자·발생시각·신고유형·발생장소는 화면에서 골라야 한다.
화면 수 6개 (성공 경로만) 9개 (업로드·실패·연결 포함) 영상을 올리는 첫 순간, 후보를 못 찾는 순간, 안전신문고로 넘어가는 순간이 모두 빠져 있었다.

상속하지 않은 것 하나. 보고보고에서 빨강 #ef1b2d은 새 사고였다. 대신고에서 빨강은 시스템 실패 전용이다 — 분석 오류, 연결 끊김, 파일 손상. AI가 찾은 사건 후보에 빨강을 쓰면 대신고가 위반을 판정하는 제품이 되어버린다.

02 — 상속한 시스템

색은 의미가 있을 때만 나타난다

무채색이 화면의 90%를 덮는다. 유채색 네 개는 각각 하나의 뜻만 갖는다. 보고보고에는 이미 확인 필요라는 오렌지 상태가 있었고, 대신고가 필요한 상태와 정확히 같은 뜻이었다.

정보 상태 5종

Product Spec §7이 요구하는 다섯 가지다. 모두 같은 배지 컴포넌트를 쓰고, 색·점·아이콘·라벨이 함께 움직인다.

출처 확인됨 사용자 확인됨 AI 추정 확인 필요 알 수 없음

행 배경도 같은 색을 쓴다. 사건 기록에서 손댈 곳이 남은 행은 그 행의 상태 색으로 옅게 칠한다 — 확인 필요는 주황, AI 추정은 파랑. 이미 정해진 값은 흰색으로 남는다. 배지를 하나씩 읽지 않아도 무엇이 남았는지 보인다.

작업 상태는 이 배지를 쓰지 않는다. 완료 / 진행 중 / 대기 / 부분 완료 / 중단 / 실패는 진행 목록의 행 아이콘과 보조 텍스트로만 표현한다. 정보의 신뢰도와 작업의 진척도가 같은 모양을 가지면 안 된다는 Core Flow §3의 요구다.

퍼센트 금지 규칙. 확신도·정확도·일치율을 어떤 숫자로도 표시하지 않는다. 원본 시스템에서 상속한 규칙의 원문은 이렇다 — 「"위험도 X%" 표현은 forbidden이므로 priority tier + 우선순위 점수로 분리 표시」. 대신고에서는 더 강하게 적용한다. 확신도·정확도·일치율을 어떤 숫자로도 표시하지 않는다. 남은 시간(ETA)도 마찬가지다.

02-B — 브랜드

망을 보는 동물

미어캣은 무리가 먹이를 찾는 동안 혼자 일어서서 주위를 살피고, 위험을 발견하면 알린다. 대신고가 하는 일이 정확히 그것이다 — 사용자가 운전하는 동안 블랙박스가 담아둔 것을 대신 훑어보고, 신고할 만한 것을 찾아 알린다. 판단하고 처벌하는 동물이 아니라 먼저 보고 알려주는 동물이라는 점이 「AI는 최종 판정을 하지 않는다」는 제품 경계와도 맞는다.

마크의 색은 우리 UI보다 깊고 청록에 가깝다. 그래서 워드마크에 #0a5c46을 쓴다 — 마크에서 뽑은 색이면서, 행동 버튼의 #0c8236보다 어두워 브랜드와 조작을 구분한다. 흰 바탕에서 7.98:1로 읽힌다.

04 — 컴포넌트 점검

컴포넌트 점검

컴포넌트 규칙과 상속 이력은 DESIGN.md가 소유한다(「출처」 문단과 Components 절). 여기에는 목업을 그리며 아직 닫지 못한 것만 남긴다.

아직 확인이 필요한 것

  • 시간 막대의 후보 밀도 — 두 번 고쳤다. 처음에는 시각을 알약으로 막대에 얹었는데 후보 두 개가 4분 간격이기만 해도 겹쳤다(측정: 11px 겹침). 시각을 떼고 번호 원만 남겼지만 그것도 부족했다 — 4분은 이 막대에서 20px인데 원이 28px이라 여전히 겹친다. 최종안은 겹치면 아래 줄로 내리고 연결선을 늘려 같은 눈금을 가리키게 하는 것이다. 시각은 오른쪽 목록에서 읽고, 막대·목록·카드가 같은 번호로 묶인다. 남은 것은 한 줄에 담을 수 없을 만큼 몰릴 때 묶음 마커로 접는 규칙이다.
  • Pretendard 로딩. 서체 스택이 'Pretendard' → 'Noto Sans KR' → … 순서라 Pretendard가 설치된 환경에서는 그대로 Pretendard로 렌더된다. 설치되지 않은 사람에게는 Google Fonts의 Noto Sans KR이 대신 뜬다. 실제 구현에서는 보고보고와 같이 Pretendard를 CDN에서 함께 불러와 모든 사용자에게 같은 자간·굵기를 보장해야 한다.
  • --font-scale 적용. 보고보고에는 1.0 / 1.1 / 1.2 배율 설정이 있다. 목업에는 배율 UI를 넣지 않았지만, 구현 시 모든 크기에 곱하기를 빼먹지 않아야 한다.
  • 시스템 실패 화면. 파일 손상은 화면 1의 목록에서 처리했지만 Core Flow §23의 분석 실패와 연결 끊김은 아직 그리지 않았다.
  • 안전신문고 입력 규칙을 실물로 확인해야 한다. 지금 화면 9는 「붙여넣기 3 · 선택 4」로 가정하고 그렸다. 신고유형 분류 이름과 시·분 선택 단위(분 단위인지 10분 단위인지)는 실제 화면을 보고 맞춰야 한다. 차량번호 표기는 확정됐다 — 12가3456과 12가 3456을 모두 허용하고, 비교·검증할 때만 내부에서 공백을 지운다. 표시는 확정값 그대로 두고 띄어쓰기 안내 문구는 넣지 않는다.
  • 신고유형 추천의 근거 표시. 지금은 「교통위반 › 진로변경 위반」을 AI 추정으로 제시만 한다. 왜 그 유형인지, 다른 후보 유형은 무엇인지 보여주는 화면이 아직 없다. Product Spec §6이 「AI는 법적 최종 판정을 하지 않는다」고 못박은 만큼 추천 근거를 보여주는 쪽이 안전하다.
